# История изменений

Все значимые изменения расширения MiniMax Agent. Формат версии следует semver, даты в формате ГГГГ-ММ-ДД.

## Как шла разработка

Проект написан агентом, а не человеком за клавиатурой. Всё, что ниже, разложено по версиям, но сама разработка шла циклом: агент читал проект, звал инструменты, правил файлы и запускал команды, а решение принимал по подтверждению пользователя.

Правила работы зафиксированы в [AGENTS.md](AGENTS.md): что менять можно, что нельзя, как выглядит панель и почему так. Каждое решение в проекте записано туда же вместе с причиной, поэтому следующий шаг делается по правилу, а не по памяти модели.

Ключевые черты процесса:

- Агентный цикл живёт только в extension host, webview не ходит в сеть и не хранит ключ.
- Каждая запись на диск и каждый запуск команды спрашивают подтверждение, правило не обходится.
- Каждое изменение поведения закрывается тестом, тест проверяет смысл, а не деталь реализации.
- Файл длиннее 400 строк делится по смыслу, а не переименовывается.
- Клиент MiniMax написан вручную на `fetch` с собственным разбором SSE, официальный SDK не используется.
- Коммиты и правила проекта на русском, тексты интерфейса и всё, что уходит в модель, на английском.

Первые версии закрывали каркас расширения и агентный цикл, дальше шли инструменты и возможности панели, в конце появились навыки, MCP, веб-поиск и работа с картинками. Полные правила и решения описаны в [AGENTS.md](AGENTS.md) и [CONTRIBUTING.md](CONTRIBUTING.md).

## 0.44.0 - 2026-11-26

### Безопасность и надёжность

- Запретные пути `minimax.denyPaths` (уровень пользователя): `.env`, ключи, `.ssh`, `secrets/` и другие закрыты для чтения, записи и поиска даже с подтверждением, `!` открывает шаблон вроде `.env.example`. Ключи, похожие на настоящие (приватный ключ PEM, AWS, GitHub, Slack, Google, `sk-`), маскируются в выводе `read_file` и `grep`.
- Агент не затирает чужую правку: `write_file` отказывает, если файл изменился вне агента с момента его чтения или записи, `edit_file` проходит, но говорит модели, что её картина файла устарела.
- Бэкапы правок агента лежат на диске редактора: откат чата возвращает файлы и после перезапуска. Предел 1000 бэкапов, 50 МБ и 14 дней.

### Панель

- Карточка подтверждения отвечает на клавиши: Enter разрешает, A разрешает всегда, Esc отклоняет. Удаление и разрушительные команды git требуют фокуса на самой карточке.
- Поиск по сохранённым чатам: заголовки фильтруются сразу, текст чатов ищет хост и показывает место совпадения.
- В списке изменённых файлов у файлов агента есть дифф «до агента ↔ сейчас» и откат одного файла без отката всего хода.
- Вывод долгой команды идёт в карточку по мере работы, а не после выхода.

### Агент

- Автопроверка: команда `minimax.verifyCommand` запускается после хода с правками, падение уходит агенту на исправление, не больше `minimax.verifyRounds` раундов подряд.
- Старые ходы, которые не влезают в контекст, сжимаются в сводку, и агент продолжает её видеть (`minimax.summarizeHistory`, включено).
- До трёх под-агентов одного ответа работают одновременно.

### Расширяемость

- Свои слэш-команды: `.minimax/commands/имя.md` (и `.claude/commands`) вызывается как `/имя`, `$ARGUMENTS` берёт остальной текст запроса.
- Команда `MiniMax: Select Project Folder` выбирает папку проекта в окне с несколькими папками, инструменты чата работают в папке его проекта.

## 0.43.5 - 2026-11-26

### Безопасность

- MCP-сервер по адресу запускается только по `https`, а `http` разрешён лишь для `localhost`, `127.0.0.1` и `[::1]`: заголовки сервера несут токен и не идут открытым текстом.
- Всегда спрашивают подтверждение удаление ветки `git push origin :ветка`, `git rebase`, `git commit --amend` и инструмент `git_worktree_remove`, правило `Always allow` их не покрывает.

### Исправления

- Битый `%` в ссылке ответа больше не роняет обработчик клика.
- Кривой JSON от MCP-сервера называется ошибкой сервера, а не сырым исключением.
- Упавший ход (лимит повторов, ошибка API) пишет время шага, как остановленный.
- Последние 8 результатов инструментов считаются среди длинных: короткие и ошибки больше не занимают их место.
- Таймер батча дельт гасится при закрытии панели, производные списки ленты считаются один раз на изменение сообщений.
- У скрепки есть `aria-label`, подпись кнопки цели следует её состоянию.

## 0.43.4 - 2026-11-26

### Безопасность

- Путь модели больше не выходит из рабочей области через ссылку: `resolveWorkspacePath` сверяет и реальный путь (symlink и junction), а `..config` больше не считается выходом наружу. `cwd` терминала идёт через ту же проверку.
- `web_fetch` закрывает IPv4 внутри IPv6 в любой записи: `::ffff:7f00:1`, `::ffff:a9fe:a9fe`, `::7f00:1`, `64:ff9b::/96`. Парсер URL сам переводит `[::ffff:127.0.0.1]` в шестнадцатеричную запись, поэтому проходила и точечная.
- Разрушительные команды git (`clean -f`, `reset --hard`, `push --force`, `stash drop`, `branch -D`, `restore`, `checkout --`) всегда спрашивают подтверждение, правило автоодобрения их не покрывает.
- Отказ `rm` в терминале видит обёртки: `env rm`, `sudo rm`, `VAR=1 rm`, `git -C sub rm`, `ri`.
- «Always allow» на карточке под-агента запоминает область вызова, а не весь инструмент.

### Исправлено

- Удалённый занятый чат больше не отправляет сообщения своей очереди.
- Stop во время сборки промпта и плана останавливает ход до запроса.
- Пузырь, заметка и ошибка хода фонового чата не попадают в открытый чат.
- Таймаут и остановка `run_terminal`, `run_cmd` и REPL убивают всё дерево процессов.
- `search_code` с `path` не подмешивает семантические результаты из других папок.
- Мягкая правка `edit_file` не задваивает отступ, когда без отступа пришла только первая строка `old_string`.
- `edit_file` оставляет `$1` и `$&` в `new_string` буквально и не пишет файл больше предела `write_file`.
- `read_file` пустого файла говорит `[empty file]`, `list_files` сортирует по имени и отказывает на пустом `paths`.
- `todo_write` называет две задачи `in_progress` сразу.
- Имя скилла без шапки на Windows это имя папки, а не весь путь.
- Подпись файла для векторов поиска это хэш текста, правка посередине той же длины больше не теряется.
- Ссылки в ответе открываются: веб-адрес через редактор, путь как файл проекта. Картинка ответа не шире панели.
- Подсказки `@` берут ответ только на последний запрос.
- Бейдж квоты работает без открытой панели (`onStartupFinished`).
- `@types/vscode` закреплён на `~1.106.0`, версии `engines`.
