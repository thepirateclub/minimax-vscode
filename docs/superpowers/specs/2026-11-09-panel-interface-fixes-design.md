# Доработка панели агента: семь замечаний от 09.11.2026

Дата: 09.11.2026
Статус: утверждён (решения пользователя получены 09.11.2026)

## 1. Контекст

Пользователь прислал семь замечаний к панели агента после фазы оформления композера:

1. Нет автоскрола ленты.
2. Переключатель размышления для M3 неочевидный, всплывающая подсказка необъяснимо упоминает другую модель.
3. Нет выбора варианта рассуждений для M3.
4. Не проверено, что расширение не выгрузится из-за большого объёма строк в чате.
5. Не сохраняется история работы.
6. Нет множественного чтения файлов.
7. Нет аккуратно оформленных действий агента и аккуратной разметки markdown.

## 2. Проверенные факты по API MiniMax

Факты сняты живыми запросами 09.11.2026 и сверены с документацией
`https://platform.minimax.io/docs/api-reference/text-anthropic-api` (revision 07.11.2026).

| Проверка | Результат |
|---|---|
| M3 + `output_config.effort=max` | HTTP 200, блоков `thinking` нет, поле игнорируется |
| M3 + `output_config.effort=low` | HTTP 200, блоков `thinking` нет, поле игнорируется |
| M3 + `thinking: {type: adaptive}` | HTTP 200, блоки `thinking` приходят |
| M3 + `thinking: {type: disabled}` | HTTP 200, блоков `thinking` нет |
| M3 + `thinking: {type: enabled}` | HTTP 200, блоки `thinking` приходят, но параметр не документирован |
| M3 + `thinking.budget_tokens` 64 / 512 / 4000 | 260 / 189 / 269 выходных токенов, зависимости от бюджета нет |
| M3 + `reasoning_effort` low / high / max | 314 / 305 / 453 символа размышления, монотонности нет |
| M3.1 Flash + `output_config.effort=low` | HTTP 200, блоки `thinking` приходят |

Вывод: **глубиной рассуждений у M3 управлять нельзя**. Документация это подтверждает:
`output_config.effort` действует только для M3.1 Flash, остальные модели поле игнорируют.
У M3 существует ровно два варианта: размышление выключено (`thinking` не передан) и
`adaptive`, где глубину выбирает сервер.

Следствие для интерфейса: показывать M3 уровни `low/medium/high` нельзя, это враньё.
Показываем два реальных варианта и говорим об этом прямо в подсказке.

## 3. Решения по пунктам

### 3.1 Единый селектор рассуждений

Один контрол в композере и один в Settings. Содержимое зависит от выбранной модели:

| Модель | Варианты | Что уходит в запрос |
|---|---|---|
| M3.1 Flash | `low`, `medium`, `high`, `xhigh`, `max` | `output_config.effort` |
| M3 | `Off`, `Adaptive` | `thinking` отсутствует / `thinking: {type: adaptive}` |

Подсказка в обоих местах описывает только текущую модель. Слово «M3.1 Flash» в подсказке
для M3 не упоминается.

В `ModelInfo` появляется поле `reasoning: 'depth' | 'variants'`. Настройки остаются
двумя: `minimax.effort` (уровни) и `minimax.thinking` (bool для M3).

### 3.2 Автоскролл

`MessageList` получает ссылку на скролл-контейнер. Лента сама уходит вниз, когда
пользователь был внизу (запас 80 px). Когда пользователь поднялся выше, лента его не
трогает, а в углу появляется кнопка «вниз» со счётчиком новых сообщений.

### 3.3 История чатов

- `activate()` больше не создаёт пустую сессию: поднимается последняя сохранённая.
- В шапке появляется кнопка истории со списком чатов: заголовок, дата, удаление.
- `persist()` вызывается в конце хода, при смене сессии и при деактивации расширения.
- Ошибка записи в `globalState` не роняет ход, а логируется.

### 3.4 Большой чат

| Ограничение | Значение | Где |
|---|---|---|
| Сообщений в DOM | 120 последних | `MessageList`, кнопка «показать ранние» |
| Сообщений в хранилище | 400 последних | `SessionStore.save` |
| Символов в одном сообщении при сохранении | 200000 | `SessionStore.save` |
| Кеш markdown | по id и длине текста | `ui/webview/markdown.ts` |

Перерисовка списка при стриме перестаёт быть квадратичной: сообщения обёрнуты в
`React.memo`, HTML markdown кешируется, пересчитывается только изменившееся сообщение.

### 3.5 Множественное чтение файлов

Инструмент `read_file` принимает `path` (один файл) или `paths` (массив). В ответе
файлы идут блоками с заголовком пути и нумерацией строк, общий лимит символов прежний
(200000). `@`-упоминания и скрепка уже умеют несколько файлов, это не меняется.

### 3.6 Оформление действий агента и markdown

Карточка действия получает иконку инструмента, человеческий заголовок («Read src/foo.ts»,
«Find needle», «Run npm test»), сводку результата (строки, совпадения, код выхода),
длительность в миллисекундах и свёрнутый по умолчанию вывод с кнопкой копирования.

Markdown рендерится отдельным модулем `ui/webview/markdown.ts`: заголовки, цитаты,
списки-чеклисты, таблицы, блоки кода с языком и кнопкой копирования.
