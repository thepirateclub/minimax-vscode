## 1. Проблема и цель

В VS Code нет расширения, которое даёт полноценного агента на моделях MiniMax. Есть `Minimax VScode Copilot` (klarkxy), но это только провайдер модели в пикере Copilot Chat: своего агентного цикла, своих инструментов и своего UI у него нет. Нужен аналог Continue / Kilo Code / Codex на API MiniMax.

Цель: расширение VS Code, в котором агент на моделях MiniMax читает и правит файлы, ищет по проекту, выполняет команды в терминале и ведёт диалог в сайдбаре.

## 2. Границы

### Входит в MVP

- Сайдбар-панель с чатом, стриминг ответа, thinking-блоки
- Собственный агентный цикл с вызовом инструментов
- Инструменты: `read_file`, `write_file`, `edit_file`, `list_files`, `search_code`, `run_terminal`
- Подтверждение опасных действий с превью диффа
- Выбор модели и глубины размышления, учёт токенов
- API-ключ в `context.secrets`, выбор эндпоинта (Global / China / custom)
- История сессий, сохранение и переключение
- Отмена активного запроса, ретраи, откат последней правки файла

### Не входит

- Inline-автодополнение, регистрация в пикере Copilot Chat, MCP, дерево чекпоинтов, мультимодальный ввод, публикация в маркетплейсе

## 3. Принятые решения

| Решение | Обоснование |
|---|---|
| Своя панель-сайдбар (webview), а не нативный Chat view | Нативный Chat view отдаёт оркестрацию агенту VS Code, промпт и набор инструментов контролировать нельзя, и путь завязан на инфраструктуру Copilot |
| Агентный цикл в extension host | В webview нет доступа к файловой системе без обхода, ключ не должен попадать в DOM, CORS |
| Свой клиент вместо `@anthropic-ai/sdk` | Заголовок `Authorization: Bearer`, нестандартное поле `output_config`, отсутствие `cache_control`, риск дрейфа версий SDK |
| Anthropic-совместимый протокол | Поддержка thinking-блоков, счёт токенов, единый формат tool_use/tool_result |
| React 18 + markdown-it в webview | Управляемый рендер потока, готовые компоненты, минимум ручного DOM |
| esbuild для двух бандлов | Extension host (Node) и webview (browser) из одного конфига, быстрые сборки |

## 4. Контракт MiniMax API

Основание: официальная документация `https://platform.minimax.io/docs/api-reference/text-anthropic-api`, снято 08.11.2026.

```
POST https://api.minimax.io/anthropic/v1/messages
Authorization: Bearer <MINIMAX_API_KEY>
Content-Type: application/json

{
  "model": "MiniMax-M3.1-Flash",
  "max_tokens": 32000,
  "output_config": { "effort": "max" },
  "system": "...",
  "messages": [ { "role": "user", "content": [ { "type": "text", "text": "..." } ] } ],
  "tools": [ { "name": "...", "description": "...", "input_schema": { ... } } ],
  "stream": true
}
```

Обязательные правила при реализации:

1. `max_tokens` включает thinking-токены. Значение по умолчанию 32000, диапазон настройки 4096-65536. `stop_reason: "max_tokens"` обрабатывается отдельным сообщением с предложением продолжить.
2. `temperature` сервером игнорируется, пользователю не показывается.
3. `output_config.effort` отправляется только для `MiniMax-M3.1-Flash`, значения `low`, `medium`, `high`, `xhigh`, `max`.
4. `thinking: {type: "disabled"}` не отправляется для `MiniMax-M3.1-Flash` (вернёт 400). Для `MiniMax-M3` по умолчанию thinking выключен, включается `adaptive`.
5. `tool_choice` не используется, поддерживается только `auto`.
6. `cache_control` не используется, сервер не поддерживает.
7. Полный `content` предыдущего ответа ассистента (thinking, text, tool_use) возвращается в следующем запросе без изменений. Пересборка текста ломает reasoning-цепочку.
8. Эндпоинты: Global `https://api.minimax.io/anthropic`, China `https://api.minimaxi.com/anthropic`. Финальный путь `/v1/messages`.
9. Коды ошибок: 2049 неверный ключ, 2057 ключ не от M Plan, 2061 модель не поддерживается тарифом, 2062 лимит M Plan исчерпан, 2066 перегрузка серверов.

## 5. Архитектура

```
VS Code (extension host)
  WebviewViewProvider  <--postMessage-->  React UI
        ^                                    |
        | события                             | команды
  Agent Loop  <-->  MiniMaxClient  <-->  api.minimax.io
        |  вызов инструментов
  Tool Registry --> File Tools | Explore Tools | Terminal
        |
  Approvals (promise-гейт) | Context Builder | Storage | Settings | Secrets
```

Инварианты:

- Слой `api/` не импортирует `vscode`
- Слой `ui/` не знает про HTTP, слой `api/` не знает про webview
- Инструменты попадают в систему только через реестр
- Webview никогда не обращается к сети

## 6. Агентный цикл

```
loop (максимум 40 итераций, настраивается):
  1. request = buildRequest(model, system, history, context, tools)
  2. for event in client.stream(request):
       thinking_delta -> emit thinking
       text_delta     -> emit text
       tool_use_start -> emit tool_start
       input_json_delta -> накопить аргументы инструмента
       message_stop   -> emit done + usage
  3. assistantBlocks = собранные блоки (как есть)
  4. если есть tool_use:
       для каждого вызова: approval -> execute -> tool_result -> в историю
       перейти к шагу 1
  5. иначе выход
```

Обработка отказов и отмен:

- Отклонённый инструмент возвращается как `tool_result` с `is_error: true` и текстом «rejected by user», чтобы модель продолжила обходным путём
- `AbortController` на каждый ход, кнопка Stop прерывает запрос, частичный ответ сохраняется в истории
- Ретраи: 2 попытки с backoff (1 с, 4 с) на 429, 5xx и сетевых сбоях; на прочих 4xx ретрая нет
- Превышение лимита итераций останавливает цикл с понятным сообщением

## 7. Инструменты

Схемы передаются модели в формате Anthropic (`input_schema`). Описания на английском.

```
read_file   { path: string, start_line?: int>=1, end_line?: int>=1 }
write_file  { path: string, content: string }
edit_file   { path: string, old_string: string, new_string: string, replace_all?: bool }
list_files  { path?: string, depth?: int>=1<=5 }
search_code { query: string, path?: string, max_results?: int>=1<=200 }
run_terminal{ command: string, cwd?: string, timeout_ms?: int<=120000 }
```

Ограничения реализации:

- `read_file` возвращает контент с номерами строк, максимум 2000 строк или 200 000 символов за один вызов
- `write_file` и `edit_file` делают бэкап оригинала в памяти сессии и на диске, затем пишут файл; лимит контента 200 000 символов
- `edit_file` при несовпадении `old_string` возвращает ошибку с указанием числа совпадений
- `list_files` игнорирует `node_modules`, `.git`, `dist`, `build`; глубина по умолчанию 2, максимум 5; максимум 300 записей
- `search_code` использует `rg` из PATH, при отсутствии переходит на JS-скан по текстовым файлам; по умолчанию 50 результатов, максимум 200
- `run_terminal` выполняется через `child_process` в корне workspace; таймаут по умолчанию 60 с, максимум 120 с; вывод обрезается до 30 000 символов
- Один и тот же инструмент с идентичными аргументами не выполняется больше трёх раз подряд: на четвёртый вызов возвращается ошибка с объяснением

## 8. Контекст

Состав запроса:

1. System prompt: роль агента, протокол работы с инструментами, сведения об окружении, правила ответа
2. Правила проекта: читаются все найденные файлы из списка `AGENTS.md`, `.github/copilot-instructions.md`, `CLAUDE.md`, `.cursorrules` в указанном порядке приоритета, общий кап 20 000 символов
3. Снимок репозитория: дерево до глубины 2, кап 300 записей, детект стека по манифестам
4. Автоконтекст: активный редактор (кап 2000 строк), выделение, список открытых файлов
5. `@`-упоминания файлов, выбранные пользователем в композере
6. История диалога

Снимок репозитория и правила проекта вычисляются один раз на сессию и обновляются командой `MiniMax: Refresh Workspace Context`.

## 9. Интерфейс

- Шапка: выбор модели, селектор effort, счётчик токенов, кнопки «новый чат», «настройки», индикатор активности
- Лента: сообщения пользователя, ответы ассеста в markdown, сворачиваемые thinking-блоки, карточки вызовов инструментов со статусом и результатом
- Превью диффа: inline unified diff с подсветкой, кнопка «открыть в редакторе» через `vscode.diff` и виртуальные документы
- Шлюз подтверждения: «Allow», «Reject», «Always allow in this session»
- Композер: Enter отправляет, Shift+Enter переносит, кнопка Stop, `@`-пикер файлов
- История: список сессий, переключение, удаление
- Строки интерфейса централизованы в `src/ui/webview/strings.ts`
- Оформление через CSS-переменные темы VS Code

## 10. Настройки, секреты, команды

## 11. Обработка ошибок

| Ситуация | Реакция |
|---|---|
| 401 или 2049 | баннер «неверный API-ключ», предложение ввести ключ заново |
| 2057 | «ключ не от M Plan, нужен подписочный ключ» |
| 2061 | «модель недоступна в вашем тарифе», подсказка сменить модель |
| 2062 | «лимит запросов M Plan исчерпан», без ретрая |
| 2066 | ретрай с backoff |
| 400 из-за `thinking: disabled` на M3.1-Flash | не отправляем этот параметр, устраняем причину в коде |
| Сетевой сбой | 2 ретрая, затем баннер с кнопкой «Retry» |
| `stop_reason: max_tokens` | предупреждение и предложение продолжить |
| Превышен лимит итераций | остановка цикла с объяснением |

## 12. Безопасность

- Ключ только в `context.secrets`, никогда не логируется и не уходит в webview
- Пути инструментов разрешаются относительно корня workspace, выход за пределы запрещён
- Запись на диск и запуск команды требуют подтверждения, поддерживается «always allow» на время сессии
- Терминальные команды выполняются с таймаутом и без интерактива
- Пользовательский ввод не попадает в shell без явного запуска пользователем

## 13. Тестирование

- Юнит: `sse.ts` (парсер потока), `convert.ts`, `diff.ts`, схемы инструментов, агентный цикл на фейковом клиенте, `context.ts`, политики подтверждений
- Интеграция: локальный HTTP-сервер с SSE-фикстурами, запрос идёт через настоящий `MiniMaxClient`, проверяются заголовки, тело, разбор потока и накопление аргументов инструментов
- Live: `npm run test:live`, один реальный запрос, ключ из `.env.local`
- Правило: новое поведение сначала покрывается падающим тестом

## 14. Критерии приёмки

1. `npm run typecheck` и `npm test` проходят.
2. `npm run package` даёт `.vsix`, расширение ставится через `code --install-extension`.
3. Панель открывается командой, чат принимает сообщение, ответ приходит потоком, thinking-блок виден и сворачивается.
4. Агент по запросу «прочитай X, поменяй Y» читает файл, показывает превью диффа, после подтверждения пишет файл.
5. `run_terminal` без подтверждения не выполняется, после подтверждения выполняется в корне workspace, вывод виден в карточке инструмента.
6. Отмена во время генерации останавливает запрос, частичный ответ сохраняется.
7. При неверном ключе показывается понятный баннер, а не стектрейс.
8. API-ключ не появляется в логах, в webview и в файлах проекта.

## 15. Риски и меры

| Риск | Мера |
|---|---|
| Отличие SSE-событий MiniMax от эталонных Anthropic | Интеграционный тест на локальном сервере плюс live-тест на этапе 1 |
| Трафик в API из тестов | live-тест один запрос, ключ только из `.env.local` |
| Модель генерирует битый JSON аргумента инструмента | Накопление `input_json_delta`, при ошибке парсинга возврат модели ошибки вместо падения |
| Бесконечный цикл вызовов | Лимит итераций и лимит повторов одного инструмента с тем же входом |
| Публикация `.env.local` | Файл в `.gitignore`, в репозитории только `.env.local.example` |
