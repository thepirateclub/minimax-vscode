# AGENTS.md

Расширение VS Code с агентом на API MiniMax: чат в сайдбаре, собственный агентный цикл, инструменты работы с файлами, поиском по проекту и терминалом. Аналог Continue / Kilo Code / Codex, но на моделях MiniMax.

## Ключевые решения проекта

- Агентный цикл живёт только в extension host. Webview (React) не ходит в сеть и не хранит ключ.
- Клиент MiniMax написан вручную на `fetch` с собственным парсером SSE. Официальный `@anthropic-ai/sdk` не используется: MiniMax требует заголовок `Authorization: Bearer`, умеет нестандартное поле `output_config` и не поддерживает `cache_control`.
- Протокол: Anthropic-совместимый эндпоинт `https://api.minimax.io/anthropic/v1/messages`.
- Ключ пользователя: M Plan (подписка Token Plan). Ключи M Plan и pay-as-you-go не взаимозаменяемы.
- Тексты интерфейса: английский. Документация проекта (этот файл, README, спеки, коммиты): русский.
- Тексты, уходящие в модель (system prompt, описания инструментов), всегда английский.
- Панель агента живёт в Secondary Side Bar, то есть справа. Настройки вынесены во вкладку `Settings` рядом с чатом.
- Файл в запросе указывается ссылкой `@путь` прямо в поле ввода. Extension host сам находит файл внутри workspace и прикладывает его содержимое к запросу. Выделенный в редакторе код уходит отдельным чипом над полем ввода.
- Ссылка на файл отображается чипом внутри поля ввода: видно только имя файла с расширением, полный путь лежит в `data-path` и в логическом тексте запроса (`@путь`). Поле ввода это `contenteditable`, чип это настоящий элемент, а не картинка, иначе каретка уезжает.
- Выбор режима, модели и уровня рассуждений живёт внутри поля ввода, в его нижнем ряду `.composer-toolbar`: режим и модель слева, переключатель рассуждения справа, сразу перед кнопкой отправки и остановки. Селекторы тихие, без рамки, рамка появляется при наведении. Нативный `<select>` не умеет иконки, поэтому селекторы собраны на своём компоненте `IconSelect` с выпадающим списком вверх, у правого селектора (`align="end"`) список растёт влево, иначе он вылезает за край панели. Рамка и фокус принадлежат обёртке `.composer-input-wrap`, а не тексту. Проверяет тест `test/unit/panel-layout.test.ts`.
- График расхода токенов живёт в шапке: один столбик на действие, входные токены приглушены, выходные акцентом, рядом счётчик за всю сессию. История расхода лежит в сохранённой сессии и переживает перезагрузку панели.
- Рассуждение управляется одним контролом, и содержимое зависит от модели. У M3.1-Flash это уровни глубины `output_config.effort`, у M3 только два варианта `Off` и `Adaptive`, потому что сервер M3 игнорирует `effort` и `reasoning_effort`. Тип управления лежит в `ModelInfo.reasoning` (`depth` или `variants`), разбор в `src/ui/webview/reasoning.ts`. Настройки `minimax.effort` и `minimax.thinking` сохранены как есть.
- Формат ответа задаёт системный промпт, а не стили: без раздела `Answer format` модель даёт простыню текста и разметка не видна.
- Подсветку синтаксиса делает собственный лексер `src/ui/webview/highlight.ts`, без внешних зависимостей: токены получают классы `tok-*`, палитра лежит в css. Вид темы читает extension host (`src/ui/theme.ts`) и передаёт панели, класс `mm-theme-*` ставится на body прямо в html, до первой отрисовки.
- Сниппет из файла проекта подписан именем файла, сгенерированный код остаётся с меткой языка. Имя даёт модель (путь файла после маркера fence в системном промпте), а панель страхуется поиском по тексту: `src/ui/webview/codeBlock.ts` ищет блок в файлах, прочитанных агентом, и подставляет `файл.ts:строка`. Клик по подписи открывает файл в редакторе на этой строке.
- Иконки берутся из канонической геометрии lucide, а не рисуются от руки: центр закрашенной области должен совпадать с центром `viewBox`, иначе иконка сидит в углу квадрата. Проверяет измеритель `test/helpers/iconGeometry.ts` в тесте `test/unit/icons.test.ts`. Исключение одно: иконки отправки и остановки, они взяты из набора иконок VS Code и потому залиты, а не контурные.
- История чатов живёт в шапке: список сохранённых сессий с удалением и `+ New chat`, активная сессия восстанавливается при запуске расширения.
- Id активной сессии пишется в состояние хоста только вместе с самой сессией: сначала список сессий, потом id. Одинокий id указывает в никуда: после перезапуска панель открывает чужой чат, а удалённый чат возвращается. Новый чат не пишет id, пока в нём нет сообщения, удалённый чат сбрасывает id. Проверяет тест `test/unit/extension-activate.test.ts`.
- Версия расширения видна в панели: хост читает `context.extension.packageJSON.version` и кладёт его в `UiState.version`, вебвью рисует бейдж с номером версии последним элементом строки вкладок (`src/ui/webview/components/Header.tsx`), справа от кнопки нового чата. Бейдж не хардкодится, не ломает высоту шапки и не сдвигает счётчик токенов. Проверяют тесты `test/unit/panel-layout.test.ts` и `test/unit/extension-activate.test.ts`.
- Номер версии живёт в `package.json` и поднимается вручную: он же попадает в имя `.vsix` и в бейдж панели. Стенд `test/visual/preview.tsx` берёт версию из манифеста, а не из константы, иначе стенд показывает чужую сборку.
- Версия поднимается по semver после каждого изменения: patch на правку, minor на новую возможность, major на несовместимое изменение. Правило действует и для пачки изменений: сначала решаем, что это для пользователя, и только потом ставим цифру.
- Инструменты git живут в `src/tools/git.ts`: модель зовёт их вместо команд git в терминале. Git запускается без оболочки, аргументы идут массивом в `src/git/cli.ts`, разбор вывода в `src/git/parse.ts`. Запуск git один на весь проект, `src/git/scm.ts` берёт тот же самый запуск.
- Чтение репозитория ничего не меняет и доступно в режиме plan: `git_status`, `git_diff`, `git_log`, `git_show`, `git_branch`, `git_blame`. Запись всегда с подтверждением и только в режиме code: `git_stage`, `git_commit`, `git_branch_create`, `git_checkout`. Коммит закрывает только индекс: пустой индекс это отказ, а не пустой коммит.
- Команды git не идут в оболочку: у `run_terminal` есть запрет на подкоманды, у которых есть свой инструмент (`gitToolFor` в `src/tools/terminal.ts`), отказ называет нужный инструмент. Без запрета модель по привычке пишет `git status` в терминал, а инструменты остаются невостребованными.
- Состояние репозитория попадает в системный промпт перед каждым ходом: раздел `Repository:` собирает `renderGitContext` из `src/agent/prompt.ts`, данные читает хост в `src/git/status.ts` и отдаёт сессии через `contextProvider`. Сам промпт агента при этом целиком не пересобирается.
- Список задач ведёт модель, пользователь только смотрит: список живёт в хосте (`RuntimeSession.todos`), инструмент `todo_write` присылает весь список снимком, хост его применяет и шлёт в панель. Галочки в виджете не кликаются, иначе панель и модель спорят за состояние. Пользователь может только очистить список целиком: кнопка ✕ в шапке виджета шлёт `clear_todos`, хост очищает `RuntimeSession.todos` и сохраняет сессию, со следующего хода модель видит пустой раздел `Tasks:`. Кнопка свёртки и кнопка очистки стоят рядом, а не одна в другой. Проверяют тесты `task-list.test.ts` и `extension-activate.test.ts`. Раздел `Tasks:` в промпте несёт список, он пуст, когда список пуст.
- Цель задаёт пользователь: виджет `Goal` над лентой, форма с лимитами по токенам, запросам и минутам, пустое поле это без лимита. Лимиты меняет только пользователь, модель не может их поднять, иначе автостоп обходится моделью. Статус цели бюджет тоже не выключает: статус меняет модель, лимиты и расход считает хост, и поднятый лимит сохраняет уже потраченное. Агент шлёт расход каждого запроса событием `usage`, хост считает его и останавливает агента с причиной `goal_limit`, статус цели остаётся `active`, лимит поднимает пользователь и работа продолжается.
- Виджеты сессии говорят словами читателя, а не именами инструментов. Строка цели в два ряда: сверху метка `Goal`, текст цели и кнопки-иконки правки и сброса, снизу расход. Рядом с расходом цели не хватало места, и ширина текста падала до нуля, а кнопка `Clear` вылезала за край панели. Неустановленный лимит не пишется (без `∞`), токены округляет общий `formatCount`. Статус цели назван словами (`Complete`, `Blocked`). Форма цели: поля лимитов подписаны, Enter сохраняет, Escape закрывает. У списка задач подписан только высокий приоритет, и он окрашен `--warn`, а не акцентом. Карточки `todo_write`, `get_goal` и `update_goal` в ленте показывают список задач и заметку, а не дамп аргументов. В открытой карточке под-агента сводка пустая: ответ ребёнка уже стоит в теле карточки. Проверяют тесты `goal-bar.test.ts`, `task-list.test.ts` и `tool-card.test.ts`.
- Цель ставится из поля ввода: кнопка с мишенью (`IconGoal`, lucide `target`) в нижнем ряду после модели переводит поле в режим цели. В этом режиме рамка поля и кнопка в цвете акцента, у поля своя подсказка, Enter ставит цель из текста поля с лимитами по умолчанию, как `/goal текст`, Escape возвращает обычный запрос. Режим работает и пока агент занят. Кнопки `Set goal` над лентой нет: без цели виджет места не занимает. В узкой панели селектор режима держит ширину, сжимается только название модели. Проверяют тесты `panel-layout.test.ts`, `goal-bar.test.ts` и `icons.test.ts`.
- Цель создаётся и правится мастером из трёх шагов: цель, лимиты, проверка (`GoalBar`, логика шагов в `src/ui/webview/goalWizard.ts`). Enter ведёт вперёд и на последнем шаге сохраняет, Shift+Enter переносит строку цели, Escape закрывает мастер. Мастер закрывается, только когда хост подтвердил цель. Команда `/goal текст` в поле ввода ставит цель сразу с лимитами по умолчанию (`DEFAULT_GOAL_FORM`, лимитов нет), `/goal` без текста открывает мастер. Команда не уходит модели и проходит, пока агент работает. Разбор команды в `src/ui/webview/slashCommand.ts`: считается только начало запроса и только целое слово. `/goal` с тем же текстом, что у текущей цели, лимиты не сбрасывает. Проверяют тесты `goal-wizard.test.ts` и `goal-bar.test.ts`.
- Чат в фоне не пишет в открытый: события хода идут в панель через `postFor` в `src/extension.ts`, только если их чат открыт, иначе текст, задачи и цель фонового чата ложились поверх открытого. Сообщения фонового чата копятся в хосте и видны при возврате. Ответ на карточку подтверждения ищет ожидающий вызов во всех чатах (`agentsByPriority`), а не только в открытом, иначе ход в фоне ждал вечно. Заметка `update_goal` живёт в карточке вызова, а не отдельной заметкой панели: заметка печатала её дважды и пропадала после перезагрузки. Проверяет тест `test/unit/extension-activate.test.ts`.
- У worktrees свои инструменты: `git_worktree_list`, `git_worktree_add`, `git_worktree_remove`. Путь worktree задаётся относительно workspace и не может выйти за его пределы, ветка при добавлении создаётся, если её ещё нет. Разбор вывода `git worktree list --porcelain` живёт в `src/git/parse.ts`.
- Под-агент это отдельный запуск агента: своя история, свой промпт (промпт родителя плюс роль), свой реестр инструментов по роли (`explore` читает, `worker` пишет, `verifier` проверяет) и тот же гейт подтверждений, запись файла ребёнком спрашивает пользователя. Глубина живёт в `ToolContext.depth`, инструмент `task` отказывает при `depth > 0`. События ребёнка идут в карточку вызова через `tool_progress`, финальный текст ребёнка это результат вызова, его токены идут в счёт сессии и в граф расхода.
- Инструмент поиска умеет то, что делает findstr: несколько слов через `patterns` (подходит любое), `ignore_case` для регистра, `path` может указывать на один файл. Скрытая папка, которую назвал модель (например `.worktrees`), ищется тоже: индекс проекта её не держит, поэтому такой поиск идёт напрямую по файлам (`src/search/find.ts`).
- Остановка агента всегда объяснена: `stopNotice` в `src/agent/stopReason.ts` превращает лимит итераций, лимит токенов и остановку пользователем в заметку панели. Молчаливая остановка это дефект.
- Отказ инструмента виден в панели: повтор одного и того же вызова с теми же аргументами и неизвестный инструмент отправляют модели `tool_result`, но шлют и события `tool_start` и `tool_end`, иначе отказ видит только модель, а читатель видит пустоту. Молчаливый отказ это дефект. Проверяет тест `test/unit/agent.test.ts`.
- История чинится перед запросом: `balanceHistory` в `src/api/history.ts` выбрасывает вызов инструмента без ответа и результат без вызова, а текст запроса никогда не сливается с сообщением, которое несёт `tool_result`. Такое сообщение MiniMax отвергает: `invalid params, tool call result does not follow tool call (2013)`, ход не начинается. Текст запроса встаёт отдельным сообщением пользователя. Откат режет историю по границе `cutHistory` из `src/agent/turns.ts`, граница не разрывает пару вызов и результат. Место запроса в истории известно точно: `Agent.run` отдаёт `requestIndex`, `AgentSession.send` возвращает его, якорь хода пишет его, а не ищет запрос по тексту, одинаковые запросы подряд сбивали поиск. Проверяют тесты `test/unit/history.test.ts`, `test/unit/turns.test.ts`, `test/unit/agent.test.ts` и `test/unit/session.test.ts`.
- Кнопки запроса стоят в одном слоте: слева от сообщения пользователя живёт либо стрелка отката, либо круговая кнопка повтора, но не обе сразу. `Go back to this point` (иконка `IconRewind`, геометрия снята с рисунка читателя) стоит, пока ход не падал. `Repeat the request` (иконка `IconRetry`) занимает тот же слот, когда ход упал: падение находит `failedRequests` в `src/ui/webview/failedRequests.ts` (заметка панели вида error или действие с красной отметкой), пока ход идёт, кнопки нет. В ряду действий справа кнопки повтора больше нет, там только время шага. Откат возвращает сообщение в поле ввода, ответы после него пропадают, агент ждёт следующей команды: возврат идёт сообщением `restore_input` в протоколе, текст запроса разбирается на текст и ссылки в `src/ui/webview/restoreInput.ts`. Откат режет историю модели по той же границе, иначе модель отвечает не с того места.
- Имя блока кода не бывает пустым: без названия читатель не знает, что за блок. Имя даёт модель (путь файла после маркера fence), панель страхуется поиском по тексту (`src/ui/webview/codeBlock.ts`), а если имя не нашлось, в шапке стоит команда, вывод которой блок цитирует (`src/ui/webview/commandHistory.ts`), иначе слово `Output`.
- Время шага стоит в последнем сообщении шага, а у карточки действия: `formatDuration` в `src/ui/format.ts` растёт от ms к s и к m. Одно правило на оба места.
- Блок аргументов не рисуется, когда аргументов нет: у `git_status` их нет вовсе, и пустая рамка читалась как пустая панель. Проверяет тест `test/unit/tool-card.test.ts`.
- Автоскролл ленты реагирует на изменение размера содержимого, а не на число сообщений: стримящийся текст растёт внутри одного сообщения. Логика вынесена в `src/ui/webview/listScroll.ts`.
- Голосовой ввод: кнопка микрофона стоит в нижнем ряду поля ввода сразу перед кнопкой отправки. Вебвью VS Code не получает доступ к микрофону (права `media` для вебвью закрыты), поэтому записывает extension host через ffmpeg: сырые отсчёты моно 16 кГц идут в stdout и лежат в памяти, до 480 секунд, остановка через `q` в stdin (`src/voice/recorder.ts`). Заголовок WAV для запроса и поиск паузы делает `src/voice/pcm.ts`. Устройство выбирает `pickMicrophone` из `src/voice/devices.ts`: настройка `minimax.microphone`, иначе устройство с `mic` или `микрофон` в имени, потому что первым в списке звуковой карты часто стоит петля `Stream Mix`. Распознаёт MiniMax `asr-1.0` тем же ключом (`src/api/speech.ts`), язык задаёт `minimax.speechLanguage`, пустое значение включает автоопределение. Состояния `idle`, `recording` и `transcribing` ведёт `VoiceController` (`src/voice/controller.ts`), ключ проверяется до открытия микрофона, любая ошибка заканчивается заметкой панели и состоянием `idle`.
- Стриминг текста речи собран на стороне панели: `asr-1.0` с `stream=true` потоково отдаёт только ответ, а на вход берёт целый файл. Каждые 3 секунды (`TICK_MS`) открытое окно записи распознаётся заново, и живой текст приходит сообщением `voice_partial`. Окно длиннее 20 секунд закрывается в самой тихой паузе последних 5 секунд (кадр 0,2 с), его текст фиксируется, начинается новое окно: запросы остаются короткими, слово не режется. Запросы не перекрываются, медленный ответ сдвигает следующий шаг. Стык окон внутри предложения идёт со строчной буквы: распознавание начинает каждое окно с заглавной. В поле живой текст стоит в нередактируемом сером `span.dictation-live` после черновика, финальный `voice_text` превращает его в обычный текст. Пробел перед речью выбирает `src/ui/webview/dictation.ts`.
- Распознавание размечает стык слов служебными символами после дефиса, и формат меняется от ответа к ответу: `какую-${ }$то`, `что-"+то`. ## Панель агента

Порядок сверху вниз:

1. Шапка: вкладки `Chat` и `Settings`, точка состояния, кнопка истории чатов с выпадающим списком сессий, кнопка нового чата, график расхода токенов и счётчик за сессию. Активная вкладка помечена скруглённой полосой под подписью, а не линией на всю ширину.
2. Лента сообщений: пузырь пользователя, markdown ответ, сворачиваемое размышление, карточки действий агента с иконкой, сводкой, таймингом и цветной точкой статуса, карточка подтверждения. В DOM живут не больше 120 последних сообщений, старые открывает кнопка `Show earlier messages`. Лента едет вниз, пока читатель внизу, кнопка `Jump to the latest` её возвращает. У блока кода шапка: имя файла со строкой, если это цитата из проекта, иначе метка языка; имя кликабельно и открывает файл.
3. Композер: чипы выделенного кода и поле ввода. В поле текст `contenteditable` с чипами файлов, скрепка в правом верхнем углу и нижний ряд: режим и модель слева, рассуждение, микрофон и кнопка отправки справа.
4. Вкладка `Settings`: ключ, endpoint, лимиты, обрезка истории, внешний вид, поиск, автоодобрение, правила проекта.

Чат и настройки смонтированы одновременно и переключаются классом `view-hidden`, поэтому черновик в поле ввода не теряется при переходе между вкладками.

- `src/extension.ts`: точка входа: activate/deactivate, регистрация панели, команд, статус-бара
- `src/api/`: слой MiniMax: клиент, парсер SSE, типы Anthropic-совместимого API, маппинг ошибок, квота лимита
- `src/api/history.ts`: обрезка истории диалога под окно контекста и грубая оценка токенов
- `src/api/embeddings.ts`: клиент эмбеддингов MiniMax (`embo-01`)
- `src/api/speech.ts`: клиент распознавания речи MiniMax (`asr-1.0`)
- `src/voice/`: голосовой ввод: выбор микрофона, запись через ffmpeg, контроллер состояний
- `src/agent/`: агентный цикл, сборка system prompt, сборка контекста, разбор ссылок на файлы, `stopReason.ts`: объяснение остановки, `turns.ts`: якоря ходов для повтора и отката
- `src/tools/`: реестр инструментов и их исполнители (файлы, поиск, терминал, git), построчный diff
- `src/search/`: индекс проекта: токенизация, лексический ранг (BM25), триграммы, чанкинг и слияние рангов, `find.ts`: поиск как в findstr
- `src/ui/`: WebviewViewProvider, протокол сообщений, шлюз подтверждений, статус-бар
- `src/ui/webview/`: React-интерфейс панели, `restoreInput.ts`: разбор запроса на текст и ссылки при откате чата
- `src/ui/webview/markdown.ts`: рендер ответов, `reasoning.ts`: контрол рассуждений, `listScroll.ts`: решение по автоскроллу, `highlight.ts`: подсветка синтаксиса, `codeBlock.ts`: имя файла в шапке блока кода, `failedRequests.ts`: какие запросы упали, `commandHistory.ts`: какая команда шла перед сообщением
- `src/ui/theme.ts`: вид темы хоста для панели
- `src/ui/format.ts`: округление чисел с приставками K, M, B и формат длительности, общее для панели и статус-бара
- `src/agent/commitMessage.ts`: системный промпт, сборка контекста и чистка текста коммита
- `src/git/scm.ts`: дифф и новые файлы репозитория, запись текста в поле SCM
- `src/ui/usageRows.ts`: строки метрик бейджа, `usageDetails.ts`: быстрый список по клику
- `src/config/`: настройки `minimax.*`, секреты, каталог моделей
- `src/storage/`: сохранение сессий в globalStorage, `usage.ts`: журнал расхода токенов за сутки
- `test/unit/`: юнит-тесты модулей
- `test/helpers/`: вспомогательные измерители для тестов, например геометрия SVG-путей
- `test/integration/`: тесты против локального SSE-сервера
- `test/live/`: реальные запросы к MiniMax
- `docs/superpowers/specs/`: дизайн-спецификации

## Code style

- TypeScript в strict-режиме, без `any` (узкие касты только с комментарием почему)
- 2 пробела, одинарные кавычки, точка с запятой в конце строки
- Идентификаторы, имена файлов, комментарии в коде, тексты UI: английский
- Комментарии объясняют «почему», а не «что»
- Модуль: одна ответственность; рост файла означает, что пора делить
- Слой `api/` не знает про `vscode`, слой `ui/` не знает про HTTP-детали
- Чистую логику вебвью выносить в отдельные `.ts` модули без React: тесты идут в окружении `node` без jsdom, компонент не проверить
- Рабочая копия в CRLF (`core.autocrlf=true`, `.gitattributes` нет), файлы, записанные инструментом в LF, конвертируются скриптом перед коммитом

## Архитектурные правила

- Инструменты объявляются только через `src/tools/registry.ts`: имя, JSON Schema, исполнитель, политика подтверждения, признак побочного эффекта
- Реестр остаётся единственным источником правды о доступности: список инструментов для модели, фильтр в системном промпте и отказ выполнять заблокированный инструмент берутся из одного места
- Сырые content-блоки ответа модели сохраняются без изменений и возвращаются в следующий запрос без перестройки: MiniMax требует непрерывности reasoning-цепочки
- События extension → webview идут только через типизированный контракт `src/ui/protocol.ts`
- Стриминг батчится в extension host перед отправкой в webview, чтобы не залить postMessage
- История диалога хранит блоки Anthropic-совместимого формата, а не пересказ
- Ссылки `@путь` разбирает `src/agent/mentions.ts`: слой агента не знает про типы webview, а webview не ходит в файловую систему
- Переход к файлу это сообщение `open_file` из `src/ui/protocol.ts`: вебвью отправляет путь и строку, extension host проверяет путь на выход за пределы workspace и открывает файл с курсором на строке
- Длинная переписка обрезается в двух местах: история диалога режется по числу сообщений и по окну контекста (`src/api/history.ts`), сохранённая сессия режется по капам (`src/storage/sessions.ts`). Ошибка записи состояния не роняет ход, чат остаётся в памяти

## Контракт MiniMax (зафиксировано)

Проверено по официальной документации 08.11.2026. Перед изменением поведения сверяться с `https://platform.minimax.io/docs/api-reference/text-anthropic-api`.

| Параметр | Факт |
|---|---|
| Эндпоинт | `https://api.minimax.io/anthropic/v1/messages` (Global), `https://api.minimaxi.com/anthropic` (China) |
| Авторизация | `Authorization: Bearer <key>`, а не `x-api-key` |
| Модели | `MiniMax-M3.1-Flash` (1M ctx), `MiniMax-M3` (1M ctx) |
| `max_tokens` | thinking-токены считаются в лимит; малое значение даёт `stop_reason: max_tokens` без текста. Значение приходит из каталога моделей (`ModelInfo.maxTokens`), сервер принимает и 200000 |
| `temperature` | игнорируется сервером |
| `output_config.effort` | `low/medium/high/xhigh/max`, только M3.1-Flash, дефолт `max` |
| `thinking` | M3.1-Flash всегда думает (`disabled` → 400); M3 по умолчанию выключен, включается `adaptive` |
| Расход токенов | входные и выходные токены приходят в `message_delta`, а `message_start` всегда содержит нули. Кеш контекста идёт отдельными полями `cache_read_input_tokens` и `cache_creation_input_tokens` |
| `tool_choice` | поддерживается только `auto` |
| `cache_control` | не поддерживается |
| `service_tier` | `standard`/`priority`, M3.1-Flash не поддерживает |
| История | полный `content` прошлого ответа (thinking/text/tool_use) возвращается без изменений |
| Ошибки | 2049 неверный ключ, 2057 не M Plan ключ, 2061 модель не в тарифе, 2062 лимит M Plan, 2066 перегрузка |
| Распознавание речи | `POST {api-root}/v1/speech_to_text`, multipart: `model=asr-1.0` и `file`. Язык в заголовке `language` (BCP-47), без заголовка автоопределение. Ответ `{text, duration, trace_id}`. До 500 секунд и 50 МБ, форматы wav, mp3, ogg, opus, flac, aac. Ключ M Plan работает. Блок `audio` в `/anthropic/v1/messages` сервер отклоняет (2013), а звуковую дорожку видео модель не слышит |
| Квота лимита | `GET {api-root}/v1/token_plan/remains`, тот же JSON, что отдаёт `mmx quota --output json`. Поля: `current_interval_remaining_percent` (окно 5 часов), `current_weekly_remaining_percent` (неделя), `remains_time` (миллисекунды до сброса). Строка выбирается по `model_name === 'general'`, иначе по префиксу `MiniMax-M`, иначе первая |
| Эмбеддинги | `POST {api-root}/v1/embeddings`, тело `{model:'embo-01', type:'query'|'db', texts:[...]}`, ответ `{vectors, base_resp}`. URL строится из базового: `baseUrl.replace(/\/anthropic\/?$/, '')`, путь под `/anthropic` не существует. Ключ M Plan получает `status_code 1002` (`rate limit exceeded(RPM)`), поэтому семантический слой выключен по умолчанию |

## Инструменты агента и политика подтверждений

| Инструмент | Подтверждение | В режиме plan | Ограничения |
|---|---|---|---|
| `read_file` | нет | доступен | строки с номерами, обрезка по лимиту, до 12 файлов за вызов через `paths` |
| `write_file` | да, с превью диффа | недоступен | путь внутри workspace, бэкап оригинала |
| `edit_file` | да, с превью диффа | недоступен | точная замена `old_string`, понятная ошибка если не найдено |
| `list_files` | нет | доступен | игнор `node_modules` и `.git`, кап по числу записей |
| `search_code` | нет | доступен | индекс проекта: BM25 и триграммы, при желании семантический слой; режим `mode`, а ещё поиск как в findstr: `patterns`, `ignore_case`, `path` |
| `git_status`, `git_diff`, `git_log`, `git_show`, `git_branch`, `git_blame` | нет | доступен | только чтение репозитория |
| `git_stage`, `git_commit`, `git_branch_create`, `git_checkout` | да, всегда | недоступен | запись в индекс, коммит и переключение веток |
| `git_worktree_list` | нет | доступен | разбор `git worktree list --porcelain` |
| `git_worktree_add`, `git_worktree_remove` | да, всегда | недоступен | путь worktree относительно workspace и не выходит за его пределы |
| `run_terminal` | да, всегда | недоступен | cwd = корень workspace, таймаут, обрезка вывода; команды git и worktree запрещены, у них есть свои инструменты |
| `todo_write` | нет | доступен | список задач сессии пишется целиком, состояние ведёт хост |
| `get_goal` | нет | доступен | чтение цели сессии с лимитами и расходом бюджета |
| `update_goal` | нет | доступен | статус цели: выполнена или заблокирована, лимиты меняет только пользователь |

Правила безопасности:

- Любая запись на диск и любой запуск команды требуют явного подтверждения пользователя
- В режиме plan инструменты с побочным эффектом скрыты от модели, а их вызов отклоняется без запроса подтверждения
- Все пути разрешаются относительно корня workspace, выход за его пределы запрещён
- Перед записью сохраняется оригинал для команды отмены
- API-ключ хранится в `context.secrets` и никогда не попадает в settings, логи и webview
- Семантический слой поиска отправляет код проекта на сервер MiniMax, поэтому он выключен по умолчанию и включается только настройкой `minimax.semanticSearch`

## Testing instructions

- Юнит-тесты: `npm test` (vitest). Парсер SSE, конвертация сообщений, diff, схемы инструментов, агентный цикл на фейковом клиенте, сборка контекста, markdown, подсветка синтаксиса, обрезка истории, автоскролл, геометрия иконок, лексический и семантический поиск, эмбеддинги, округление чисел, журнал расхода токенов, строки метрик бейджа, текст коммита, разбор диффа, манифест расширения.
- Окружение тестов `node`, jsdom нет: React-компоненты вебвью не тестируются, вместо них проверяется логика в отдельных `.ts` модулях
- Геометрия иконок проверяется измерителем `test/helpers/iconGeometry.ts`: центр закрашенной области должен совпадать с центром `viewBox`
- Манифест расширения проверяется тестом `test/unit/manifest.test.ts`: команда должна попасть в палитру, а кнопка в Source Control в меню `scm/title` с точной группой `navigation`
- Интеграционные: `npm test` (vitest). Локальный HTTP-сервер отдаёт SSE-фикстуры, запрос идёт через настоящий клиент.
- Live: `npm run test:live`. Требует `MINIMAX_API_KEY` в `.env.local`, файл в `.gitignore`.
- Новое поведение сначала покрывается падающим тестом, затем пишется реализация.
- Перед коммитом: `npm run typecheck && npm test` зелёные.

## PR & commit conventions

- Ветка от `main`, в `main` не пушим напрямую
- Коммитим только свои файлы: `git add -- <явные пути>`, никогда `git add -A`
- Сообщения коммитов на русском в стиле Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`)
- Секреты никогда не коммитятся, `.env.local` в `.gitignore`

## Вне MVP

- inline-автодополнение в редакторе
- MCP-серверы
- дерево чекпоинтов (откат к сообщению по кнопке уже есть)
- мультимодальный ввод (изображения, видео)
- регистрация модели в пикере Copilot Chat
- публикация в VS Code Marketplace

## Definition of Done

- `npm run typecheck` и `npm test` проходят
- расширение собирается в `.vsix` и ставится через `code --install-extension`
- чат и его история переживают перезагрузку окна, прошлый чат открывается из шапки
- агент в реальном проекте читает файл, вносит правку, показывает дифф и запускает команду по подтверждению
- API-ключ не покидает `context.secrets`
