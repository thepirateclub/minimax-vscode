# AGENTS.md

Расширение VS Code с агентом на API MiniMax: чат в сайдбаре, собственный агентный цикл, инструменты работы с файлами, поиском по проекту и терминалом. Аналог Continue / Kilo Code / Codex, но на моделях MiniMax.

## Ключевые решения проекта

- Агентный цикл живёт только в extension host. Webview (React) не ходит в сеть и не хранит ключ.
- Клиент MiniMax написан вручную на `fetch` с собственным парсером SSE. Официальный `@anthropic-ai/sdk` не используется: MiniMax требует заголовок `Authorization: Bearer`, умеет нестандартное поле `output_config` и не поддерживает `cache_control`.
- Протокол: Anthropic-совместимый эндпоинт `https://api.minimax.io/anthropic/v1/messages`.
- Ключ пользователя: M Plan (подписка Token Plan). Ключи M Plan и pay-as-you-go не взаимозаменяемы.
- Тексты интерфейса: английский. Документация проекта (этот файл, README, спеки, коммиты): русский.
- Тексты, уходящие в модель (system prompt, описания инструментов), всегда английский.
- Панель агента живёт в Secondary Side Bar, то есть справа. Настройки вынесены во вкладку `Settings` рядом с чатом.
- Файл в запросе указывается ссылкой `@путь` прямо в поле ввода. Extension host сам находит файл внутри workspace и прикладывает его содержимое к запросу. Выделенный в редакторе код уходит отдельным чипом над полем ввода.
- Ссылка на файл отображается чипом внутри поля ввода: видно только имя файла с расширением, полный путь лежит в `data-path` и в логическом тексте запроса (`@путь`). Поле ввода это `contenteditable`, чип это настоящий элемент, а не картинка, иначе каретка уезжает.
- Выбор модели и уровня рассуждений живёт под полем ввода промпта. Селекторы узкие и с инлайновыми SVG-иконками: нативный `<select>` не умеет иконки, поэтому ряд собран на своём компоненте `IconSelect` с выпадающим списком вверх.
- График расхода токенов живёт в шапке: один столбик на действие, входные токены приглушены, выходные акцентом, рядом счётчик за всю сессию. История расхода лежит в сохранённой сессии и переживает перезагрузку панели.
- Рассуждение управляется одним контролом, и содержимое зависит от модели. У M3.1-Flash это уровни глубины `output_config.effort`, у M3 только два варианта `Off` и `Adaptive`, потому что сервер M3 игнорирует `effort` и `reasoning_effort`. Тип управления лежит в `ModelInfo.reasoning` (`depth` или `variants`), разбор в `src/ui/webview/reasoning.ts`. Настройки `minimax.effort` и `minimax.thinking` сохранены как есть.
- Формат ответа задаёт системный промпт, а не стили: без раздела `Answer format` модель даёт простыню текста и разметка не видна.
- Подсветку синтаксиса делает собственный лексер `src/ui/webview/highlight.ts`, без внешних зависимостей: токены получают классы `tok-*`, палитра лежит в css. Вид темы читает extension host (`src/ui/theme.ts`) и передаёт панели, класс `mm-theme-*` ставится на body прямо в html, до первой отрисовки.
- Сниппет из файла проекта подписан именем файла, сгенерированный код остаётся с меткой языка. Имя даёт модель (путь файла после маркера fence в системном промпте), а панель страхуется поиском по тексту: `src/ui/webview/codeBlock.ts` ищет блок в файлах, прочитанных агентом, и подставляет `файл.ts:строка`. Клик по подписи открывает файл в редакторе на этой строке.
- Иконки берутся из канонической геометрии lucide, а не рисуются от руки: центр закрашенной области должен совпадать с центром `viewBox`, иначе иконка сидит в углу квадрата. Проверяет измеритель `test/helpers/iconGeometry.ts` в тесте `test/unit/icons.test.ts`. Исключение одно: иконки отправки и остановки, они взяты из набора иконок VS Code и потому залиты, а не контурные.
- История чатов живёт в шапке: список сохранённых сессий с удалением и `+ New chat`, активная сессия восстанавливается при запуске расширения.
- Id активной сессии пишется в состояние хоста только вместе с самой сессией: сначала список сессий, потом id. Одинокий id указывает в никуда: после перезапуска панель открывает чужой чат, а удалённый чат возвращается. Новый чат не пишет id, пока в нём нет сообщения, удалённый чат сбрасывает id. Проверяет тест `test/unit/extension-activate.test.ts`.
- Автоскролл ленты реагирует на изменение размера содержимого, а не на число сообщений: стримящийся текст растёт внутри одного сообщения. Логика вынесена в `src/ui/webview/listScroll.ts`.
- Кнопка `Attach` убрана из ряда действий: скрепка стоит в правом верхнем углу поля ввода и не забирает фокус.
- Бейдж в статус-баре показывает остаток 5-часового окна лимита в процентах, а не расход токенов. Источник: `GET {api-root}/v1/token_plan/remains`. Клик по бейджу открывает список чисел: расход за сутки, остаток за неделю, остаток за 5 часов и кэш-хит в процентах. Проценты окон берутся с сервера, а суточный расход и кэш-хит считаются локально по журналу `src/storage/usage.ts`: сервер отдаёт только проценты и времена окон.
- Режимы агента: `plan` только читает, `code` даёт полный доступ. Доступность инструмента задаёт флаг `sideEffect` у записи `ToolEntry`, а решение принимает реестр `src/tools/registry.ts`.
- Режим живёт в настройке `minimax.mode`, переключается селектором под полем ввода, во вкладке Settings и командой `MiniMax: Set Agent Mode`. Меняется со следующего хода: агент пересоздаётся вместе с системным промптом, история сессии сохраняется.
- Вторичная боковая панель появилась в VS Code 1.106, поэтому `engines.vscode` = `^1.106.0`.
- Статус агента в шапке и в карточке действия рисуется цветной точкой, а не текстом. Текст состояния остаётся в `title` и `aria-label`, иначе статус не прочитать с клавиатуры. Точка в шапке пульсирует, пока агент работает. Точка в карточке действия мигает серым (`var(--muted)`) только пока действие выполняется, а готовое действие горит ровным цветом: зелёным при успехе, красным при ошибке, без анимации. Класс точки и правило таблицы стилей должны совпадать: разметка даёт `tool-dot-done`, а стиль описан как `.tool-dot.tool-dot-done`, иначе точка остаётся серой и успех с ошибкой не отличить. Проверяет тест `test/unit/tool-card.test.ts`.
- Размер шрифта панели задаётся CSS-переменной `--mm-font-base` (база 13px), а не масштабированием через `transform`: все размеры в css переведены в `calc(var(--mm-font-base) * ratio)`. Настройка `minimax.fontSize`.
- Карточка действия приглушена: без рамки и без подложки, заголовок обычным начертанием, меньшим кеглем и приглушённым цветом, полный цвет возвращается при наведении. Ошибка отмечена прямой чертой слева в том же цвете, что и точка ошибки: скруглённая рамка рисовала полукруг и читалась как украшение, а цвет темы делал отметку серой. Панель действий не должна спорить с текстом ответа. Проверяет тест `test/unit/tool-card.test.ts`.
- Запись и изменение файла показываются в карточке действия как диф. Агент берёт изменение до записи: после записи файл на диске уже новый и изменение пропало. Диф считает `buildPreview` из `src/tools/preview.ts`, карточка рисует его через `DiffView` без шапки с путём, имя файла уже названо в заголовке. В сохранённой сессии длинный диф обрезается, `MAX_STORED_DIFF_LINES` в `src/storage/sessions.ts`. Проверяют тесты `test/unit/agent.test.ts`, `test/unit/tool-card.test.ts`, `test/unit/extension-activate.test.ts` и `test/unit/sessions-store.test.ts`.
- Диф цветной: добавленные строки зелёные, удалённые красные. Своя палитра `--diff-add-fg` и `--diff-remove-fg` в css, а не токены редактора: в темах они бледнеют и изменение перестаёт читаться. Маркер строки несёт тот же цвет. В шапке карточки стоит размер изменения `+N` и `-N`, его считает `diffStats` из `src/ui/webview/diffStats.ts`, счётчик остаётся на свёрнутой карточке. Пустая половина не показывается: у нового файла нет `-0`, ноль в красном читается как ошибка. Проверяют тесты `test/unit/diff-stats.test.ts` и `test/unit/tool-card.test.ts`.
- Вывод команды рисуется как терминал: команда стоит отдельной строкой с `$`, строки ошибки красные, сводка карточки молчит, если команда прошла. Разбор вывода в `src/ui/webview/terminalOutput.ts`, вид в `TerminalView`. Проверяют тесты `test/unit/terminal-output.test.ts` и `test/unit/tool-card.test.ts`.
- Команда не печатается дважды: в открытой карточке она стоит в блоке терминала, заголовок называет только действие. В свёрнутой карточке тело скрыто, поэтому заголовок команду повторяет. Код возврата живёт только в заголовке, обёртка инструмента `Command failed with exit code N` в транскрипт не попадает.
- Карточка команды показывает терминал с самого начала: пока команда работает, вывода ещё нет, но дамп аргументов инструмента не появляется. Поток ошибок помечен меткой `stderr`, длинная команда занимает три строки и раскрывается по клику, справа оставлено место под кнопку копирования.
- Повтор одной ошибки в панели не дублируется, заметку добавляет `appendNotice` из `src/ui/webview/notices.ts`.
- Ошибка панели показывается заметкой, а не частью ответа модели: у сообщения роль `notice`, полоса слева в цвете ошибки. Текст чистит `fileErrorMessage` из `src/ui/fileError.ts`: дамп редактора с URI и `Detail:` в панель не попадает, там короткая фраза. Проверяют тесты `test/unit/file-error.test.ts`, `test/unit/message-list.test.ts` и `test/unit/extension-activate.test.ts`.
- Причину отказа разбирают по веткам: отказ в доступе и занятый файл не зовут файл отсутствующим, а общий признак `Unable to read file` ничего не говорит о причине. Обёртка `Command failed with exit code N` режется только в начале вывода: строка вывода с таким же текстом остаётся на месте.
- Класс в разметке без правила в стилях это тупик: у каждого класса заметки есть правило. Проверяет тест `test/unit/message-list.test.ts`.
- Правка без сохранённого диффа показывается как дифф: модуль `src/ui/webview/editDiff.ts` собирает его из `old_string` и `new_string`. Упавшая правка и `replace_all` остаются дампом, дифф там соврал бы. Проверяет тест `test/unit/edit-diff.test.ts`.
- Время работы и точка состояния стоят в правом краю заголовка карточки, оба в обёртке `.tool-tail` с `margin-left: auto`. Заголовок прижат к левому краю, счётчики изменения остаются рядом с названием.
- Чтение файла показывается как сам файл: номера строк в отдельной колонке `.file-read-num`, текст с подсветкой языка файла, путь не повторяется, его называет заголовок. Вывод разбирает `parseReadOutput` из `src/ui/webview/fileRead.ts`, рисует `FileReadView`. Проверяют тесты `test/unit/file-read.test.ts` и `test/unit/tool-card.test.ts`.
- `read_file` читает диапазон строк через `start_line` и `end_line`, диапазон стоит в заголовке карточки, например `Read src/app.ts 10-40`. Модель знает про параметры из описания инструмента и из строки промпта.
- Заголовок карточки действия уже называет файл, поэтому сводка путь не повторяет: если результат инструмента заканчивается путём, сводка пустая, а текст ошибки остаётся. Правило общее для всех инструментов, проверяет тест `test/unit/tool-card.test.ts`.
- Панельки действий и панельки кода сворачиваются независимо: `minimax.collapseTools` (карточка действия остаётся одной строкой) и `minimax.collapseCode` (у блока кода остаётся шапка с именем файла). Обе по умолчанию выключены. Решение о состоянии карточки лежит в `src/ui/webview/toolCardState.ts`: карточка следует за настройкой, а клик читателя запоминается как перекрытие. Эффект, который только сворачивает карточки, ломал обратный переход, поэтому карточка выводит состояние из настройки, а не хранит его. Блок кода сворачивается классом `collapsed` на `.code-block` и кнопкой `.code-toggle` в шапке, клик по ней разворачивает блок. Настройки приходят в вебвью в `UiState`, иначе чат не узнает о них, пока не откроет вкладку Settings. Проверяют тесты `test/unit/tool-card-state.test.ts`, `test/unit/tool-card.test.ts`, `test/unit/markdown.test.ts` и `test/unit/manifest.test.ts`.
- Расход токенов округляется с приставками K, M, B, функция `formatCount` в `src/ui/format.ts`. Она лежит в общем слое, а не в вебвью: тем же правилом считает и статус-бар.
- Кнопка отправки стоит внутри поля ввода, в его правом нижнем углу, и рисуется иконкой, а не текстом: `IconSend` и `IconStop` в `src/ui/webview/icons.tsx`. Селекторы режима, модели и рассуждения стоят отдельной строкой под полем. Обе иконки взяты из набора иконок VS Code, это шрифт `codicon.ttf` из поставки редактора: стрелка отправки глиф `send` (0xEC0F), квадрат остановки глиф `debug-stop` (0xEAC7). Контуры лежат в `src/ui/webview/codicons.ts`, они выровнены в сетку 16 на 16 единиц и заливаются: общий компонент `Svg` принимает проп `filled`, без него глиф не нарисуется. Размер 14 пикселей и приглушённый цвет `var(--muted)` такие же, как у скрепки, при наведении стрелка светлеет до `var(--vscode-foreground)`, а кнопка остановки оставляет красный. Пропорции, направление носа, дырка в стрелке, размер и цвет проверяет тест `test/unit/icons.test.ts`.
- График расхода токенов растянут на всю ширину шапки, а столбики держат свою ширину: фон графика тянется, шаги не расплываются. Столбик входных токенов залит смешанным цветом (`color-mix`), а не полупрозрачным: сквозь `opacity` просвечивала сетка графика. Ряд графика стоит на обеих вкладках, иначе шапка меняет высоту и панель прыгает. Проверяет тест `test/unit/panel-layout.test.ts`.
- Лимит ответа `max_tokens` берётся из каталога моделей (`ModelInfo.maxTokens`), а не из настройки: `minimax.maxTokens` помечена устаревшей и игнорируется.
- Обрезка истории диалога настраивается: `minimax.historyMaxMessages` (сколько последних сообщений оставить) и `minimax.contextThreshold` (процент окна контекста). До этого порог был жёстко 50%.
- Поиск по проекту идёт через индекс в `src/search/`: лексический слой (BM25 и триграммы) работает офлайн и включён всегда, семантический слой (эмбеддинги MiniMax) опционален и выключен по умолчанию, потому что отправляет код проекта на сервер.
- Режим поиска задаётся параметром `mode` у инструмента `search_code` (`auto`, `lexical`, `semantic`, `hybrid`), а не отдельным инструментом: реестр остаётся единственным источником правды.
- Индекс проекта живёт в extension host, строится лениво в фоне, обновляется по файловому watcher'у `**/*` и перестраивается командой `MiniMax: Rebuild Project Index`.
- Генерация текста коммита живёт в панели Source Control: кнопка со звёздочкой в меню `scm/title`, группа `navigation` ровно так же, как у встроенного git. Кнопка `view/title` с `viewId: workbench.scm` в VS Code 1.145 не рисуется, поэтому меню `scm/title` остаётся единственным. Действия SCM видны, когда панель в фокусе, а не всегда.
- Дифф для текста коммита берётся git CLI (`src/git/scm.ts`), а не API расширения git: версия API не влияет на разбор. Новые файлы в дифф не попадают, поэтому они собираются отдельно через `git ls-files --others` и добавляются в список файлов как добавленные. Текст коммита кладётся в поле SCM через API git-расширения, а если репозитория нет, в буфер обмена.
- Промпт для текста коммита английский, ответ русский: так пишется история проекта. Ответ вычищается до строки Conventional Commits, лишние кавычки и ограды убираются. Тип коммита тоже чинится: «choge» становится «chore», «feature» превращается в «feat», незнакомое слово падает в `chore`.

- Внешний вид панели подчиняется `docs/styleguide.md`: кегли только из шкалы `--fs-xs/sm/md/base`, радиусы `--radius-sm` и `--radius`, отступы по шкале 2/4/6/8/12/16/24/32, одна тень `--shadow`, цвета смысла `--ok`, `--err`, `--warn` поверх цветов темы. Токены объявлены на `body`, а не на `:root`: размер шрифта меняется на `body`, и производные от него токены должны считаться там же. Соблюдение проверяет тест `test/unit/styleguide.test.ts`, глазами проверяет стенд `npm run preview` (`test/visual/`).
- Акцент `--accent` означает только интерактив и активное состояние. Заголовки ответа, маркеры списков и метки языка блока кода акцентом не красятся. Пузырь пользователя на спокойной подложке, а не цветом кнопки: заливка делала вопрос громче ответа.
- Кнопка без подписи рисуется SVG-иконкой: `IconPlus`, `IconClose`, шеврон `Chevron` поверх `IconCaret`. Текстовые `+`, `×`, `▸`, `▾` не используются, исключение одно: крестик чипа файла внутри `contenteditable`. В группе текстовых кнопок одна основная, в карточке подтверждения это `Allow`.

## Панель агента

Порядок сверху вниз:

1. Шапка: вкладки `Chat` и `Settings`, точка состояния, кнопка истории чатов с выпадающим списком сессий, кнопка нового чата, график расхода токенов и счётчик за сессию. Активная вкладка помечена скруглённой полосой под подписью, а не линией на всю ширину.
2. Лента сообщений: пузырь пользователя, markdown ответ, сворачиваемое размышление, карточки действий агента с иконкой, сводкой, таймингом и цветной точкой статуса, карточка подтверждения. В DOM живут не больше 120 последних сообщений, старые открывает кнопка `Show earlier messages`. Лента едет вниз, пока читатель внизу, кнопка `Jump to the latest` её возвращает. У блока кода шапка: имя файла со строкой, если это цитата из проекта, иначе метка языка; имя кликабельно и открывает файл.
3. Композер: чипы выделенного кода, поле ввода `contenteditable` с чипами файлов и скрепкой в правом верхнем углу, под ним узкий ряд селекторов режима, модели и рассуждения, а в правом нижнем углу круглая кнопка отправки иконкой.
4. Вкладка `Settings`: ключ, endpoint, лимиты, обрезка истории, внешний вид, поиск, автоодобрение, правила проекта.

Чат и настройки смонтированы одновременно и переключаются классом `view-hidden`, поэтому черновик в поле ввода не теряется при переходе между вкладками.

## Code style

- TypeScript в strict-режиме, без `any` (узкие касты только с комментарием почему)
- 2 пробела, одинарные кавычки, точка с запятой в конце строки
- Идентификаторы, имена файлов, комментарии в коде, тексты UI: английский
- Комментарии объясняют «почему», а не «что»
- Модуль: одна ответственность; рост файла означает, что пора делить
- Слой `api/` не знает про `vscode`, слой `ui/` не знает про HTTP-детали
- Чистую логику вебвью выносить в отдельные `.ts` модули без React: тесты идут в окружении `node` без jsdom, компонент не проверить
- Рабочая копия в CRLF (`core.autocrlf=true`, `.gitattributes` нет), файлы, записанные инструментом в LF, конвертируются скриптом перед коммитом

## Архитектурные правила

- Инструменты объявляются только через `src/tools/registry.ts`: имя, JSON Schema, исполнитель, политика подтверждения, признак побочного эффекта
- Реестр остаётся единственным источником правды о доступности: список инструментов для модели, фильтр в системном промпте и отказ выполнять заблокированный инструмент берутся из одного места
- Сырые content-блоки ответа модели сохраняются без изменений и возвращаются в следующий запрос без перестройки: MiniMax требует непрерывности reasoning-цепочки
- События extension → webview идут только через типизированный контракт `src/ui/protocol.ts`
- Стриминг батчится в extension host перед отправкой в webview, чтобы не залить postMessage
- История диалога хранит блоки Anthropic-совместимого формата, а не пересказ
- Ссылки `@путь` разбирает `src/agent/mentions.ts`: слой агента не знает про типы webview, а webview не ходит в файловую систему
- Переход к файлу это сообщение `open_file` из `src/ui/protocol.ts`: вебвью отправляет путь и строку, extension host проверяет путь на выход за пределы workspace и открывает файл с курсором на строке
- Длинная переписка обрезается в двух местах: история диалога режется по числу сообщений и по окну контекста (`src/api/history.ts`), сохранённая сессия режется по капам (`src/storage/sessions.ts`). Ошибка записи состояния не роняет ход, чат остаётся в памяти

## Контракт MiniMax (зафиксировано)

Проверено по официальной документации 08.11.2026. Перед изменением поведения сверяться с `https://platform.minimax.io/docs/api-reference/text-anthropic-api`.

| Параметр | Факт |
|---|---|
| Эндпоинт | `https://api.minimax.io/anthropic/v1/messages` (Global), `https://api.minimaxi.com/anthropic` (China) |
| Авторизация | `Authorization: Bearer <key>`, а не `x-api-key` |
| Модели | `MiniMax-M3.1-Flash` (1M ctx), `MiniMax-M3` (1M ctx) |
| `max_tokens` | thinking-токены считаются в лимит; малое значение даёт `stop_reason: max_tokens` без текста. Значение приходит из каталога моделей (`ModelInfo.maxTokens`), сервер принимает и 200000 |
| `temperature` | игнорируется сервером |
| `output_config.effort` | `low/medium/high/xhigh/max`, только M3.1-Flash, дефолт `max` |
| `thinking` | M3.1-Flash всегда думает (`disabled` → 400); M3 по умолчанию выключен, включается `adaptive` |
| Расход токенов | входные и выходные токены приходят в `message_delta`, а `message_start` всегда содержит нули. Кеш контекста идёт отдельными полями `cache_read_input_tokens` и `cache_creation_input_tokens` |
| `tool_choice` | поддерживается только `auto` |
| `cache_control` | не поддерживается |
| `service_tier` | `standard`/`priority`, M3.1-Flash не поддерживает |
| История | полный `content` прошлого ответа (thinking/text/tool_use) возвращается без изменений |
| Ошибки | 2049 неверный ключ, 2057 не M Plan ключ, 2061 модель не в тарифе, 2062 лимит M Plan, 2066 перегрузка |
| Квота лимита | `GET {api-root}/v1/token_plan/remains`, тот же JSON, что отдаёт `mmx quota --output json`. Поля: `current_interval_remaining_percent` (окно 5 часов), `current_weekly_remaining_percent` (неделя), `remains_time` (миллисекунды до сброса). Строка выбирается по `model_name === 'general'`, иначе по префиксу `MiniMax-M`, иначе первая |
| Эмбеддинги | `POST {api-root}/v1/embeddings`, тело `{model:'embo-01', type:'query'|'db', texts:[...]}`, ответ `{vectors, base_resp}`. URL строится из базового: `baseUrl.replace(/\/anthropic\/?$/, '')`, путь под `/anthropic` не существует. Ключ M Plan получает `status_code 1002` (`rate limit exceeded(RPM)`), поэтому семантический слой выключен по умолчанию |

## Инструменты агента и политика подтверждений

| Инструмент | Подтверждение | В режиме plan | Ограничения |
|---|---|---|---|
| `read_file` | нет | доступен | строки с номерами, обрезка по лимиту, до 12 файлов за вызов через `paths` |
| `write_file` | да, с превью диффа | недоступен | путь внутри workspace, бэкап оригинала |
| `edit_file` | да, с превью диффа | недоступен | точная замена `old_string`, понятная ошибка если не найдено |
| `list_files` | нет | доступен | игнор `node_modules` и `.git`, кап по числу записей |
| `search_code` | нет | доступен | индекс проекта: BM25 и триграммы, при желании семантический слой; режим `mode` |
| `run_terminal` | да, всегда | недоступен | cwd = корень workspace, таймаут, обрезка вывода |

Правила безопасности:

- Любая запись на диск и любой запуск команды требуют явного подтверждения пользователя
- В режиме plan инструменты с побочным эффектом скрыты от модели, а их вызов отклоняется без запроса подтверждения
- Все пути разрешаются относительно корня workspace, выход за его пределы запрещён
- Перед записью сохраняется оригинал для команды отмены
- API-ключ хранится в `context.secrets` и никогда не попадает в settings, логи и webview
- Семантический слой поиска отправляет код проекта на сервер MiniMax, поэтому он выключен по умолчанию и включается только настройкой `minimax.semanticSearch`

## Testing instructions

- Юнит-тесты: `npm test` (vitest). Парсер SSE, конвертация сообщений, diff, схемы инструментов, агентный цикл на фейковом клиенте, сборка контекста, markdown, подсветка синтаксиса, обрезка истории, автоскролл, геометрия иконок, лексический и семантический поиск, эмбеддинги, округление чисел, журнал расхода токенов, строки метрик бейджа, текст коммита, разбор диффа, манифест расширения.
- Окружение тестов `node`, jsdom нет: React-компоненты вебвью не тестируются, вместо них проверяется логика в отдельных `.ts` модулях
- Геометрия иконок проверяется измерителем `test/helpers/iconGeometry.ts`: центр закрашенной области должен совпадать с центром `viewBox`
- Манифест расширения проверяется тестом `test/unit/manifest.test.ts`: команда должна попасть в палитру, а кнопка в Source Control в меню `scm/title` с точной группой `navigation`
- Интеграционные: `npm test` (vitest). Локальный HTTP-сервер отдаёт SSE-фикстуры, запрос идёт через настоящий клиент.
- Live: `npm run test:live`. Требует `MINIMAX_API_KEY` в `.env.local`, файл в `.gitignore`.
- Новое поведение сначала покрывается падающим тестом, затем пишется реализация.
- Перед коммитом: `npm run typecheck && npm test` зелёные.

## PR & commit conventions

- Ветка от `main`, в `main` не пушим напрямую
- Коммитим только свои файлы: `git add -- <явные пути>`, никогда `git add -A`
- Сообщения коммитов на русском в стиле Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`)
- Секреты никогда не коммитятся, `.env.local` в `.gitignore`

## Вне MVP

- inline-автодополнение в редакторе
- MCP-серверы
- дерево чекпоинтов и откат сессии
- мультимодальный ввод (изображения, видео)
- регистрация модели в пикере Copilot Chat
- публикация в VS Code Marketplace

## Definition of Done

- `npm run typecheck` и `npm test` проходят
- расширение собирается в `.vsix` и ставится через `code --install-extension`
- чат и его история переживают перезагрузку окна, прошлый чат открывается из шапки
- агент в реальном проекте читает файл, вносит правку, показывает дифф и запускает команду по подтверждению
- API-ключ не покидает `context.secrets`
