# AGENTS.md

Расширение VS Code с агентом на API MiniMax: чат в сайдбаре, собственный агентный цикл, инструменты работы с файлами, поиском по проекту и терминалом. Аналог Continue / Kilo Code / Codex, но на моделях MiniMax.

## Ключевые решения проекта

- Агентный цикл живёт только в extension host. Webview (React) не ходит в сеть и не хранит ключ.
- Клиент MiniMax написан вручную на `fetch` с собственным парсером SSE. Официальный `@anthropic-ai/sdk` не используется: MiniMax требует заголовок `Authorization: Bearer`, умеет нестандартное поле `output_config` и не поддерживает `cache_control`.
- Протокол: Anthropic-совместимый эндпоинт `https://api.minimax.io/anthropic/v1/messages`.
- Ключ пользователя: M Plan (подписка Token Plan). Ключи M Plan и pay-as-you-go не взаимозаменяемы.
- Тексты интерфейса: английский. Документация проекта (этот файл, README, спеки, коммиты): русский.
- Тексты, уходящие в модель (system prompt, описания инструментов), всегда английский.
- Панель агента живёт в Secondary Side Bar, то есть справа. Настройки вынесены во вкладку `Settings` рядом с чатом.
- Файл в запросе указывается ссылкой `@путь` прямо в поле ввода. Extension host сам находит файл внутри workspace и прикладывает его содержимое к запросу. Выделенный в редакторе код уходит отдельным чипом над полем ввода.
- Ссылка на файл отображается чипом внутри поля ввода: видно только имя файла с расширением, полный путь лежит в `data-path` и в логическом тексте запроса (`@путь`). Поле ввода это `contenteditable`, чип это настоящий элемент, а не картинка, иначе каретка уезжает.
- Выбор режима, модели и уровня рассуждений живёт внутри поля ввода, в его нижнем ряду `.composer-toolbar`: режим и модель слева, переключатель рассуждения справа, сразу перед кнопкой отправки и остановки. Селекторы тихие, без рамки, рамка появляется при наведении. Нативный `<select>` не умеет иконки, поэтому селекторы собраны на своём компоненте `IconSelect` с выпадающим списком вверх, у правого селектора (`align="end"`) список растёт влево, иначе он вылезает за край панели. Рамка и фокус принадлежат обёртке `.composer-input-wrap`, а не тексту. Проверяет тест `test/unit/panel-layout.test.ts`.
- График расхода токенов живёт в шапке: один столбик на действие, входные токены приглушены, выходные акцентом, рядом счётчик за всю сессию. История расхода лежит в сохранённой сессии и переживает перезагрузку панели.
- Рассуждение управляется одним контролом, и содержимое зависит от модели. У M3.1-Flash это уровни глубины `output_config.effort`, у M3 только два варианта `Off` и `Adaptive`, потому что сервер M3 игнорирует `effort` и `reasoning_effort`. Тип управления лежит в `ModelInfo.reasoning` (`depth` или `variants`), разбор в `src/ui/webview/reasoning.ts`. Настройки `minimax.effort` и `minimax.thinking` сохранены как есть. Клиент ставит `output_config`, только когда зовущий прислал `effort`: каталог моделей решает через `supportsEffort` (`effortFor` в `src/extension.ts`), имя модели в клиенте не хардкодится. Проверяет тест `test/unit/client.test.ts`.
- Формат ответа задаёт системный промпт, а не стили: без раздела `Answer format` модель даёт простыню текста и разметка не видна.
- Предел размера файла — 400 строк, и он касается всех файлов проекта: исходников в `src` и тестов в `test`. Предел проверяет тест `test/unit/file-size.test.ts`. Файл длиннее предела это дефект: его режут по смыслу, а не переименовывают в другое имя. Сейчас самый длинный файл проекта — 400 строк (`src/ui/webview/components/Composer.tsx`), следующая правка композера начинается с выноса логики в модуль. Лист стилей разрезан на осмысленные компоненты панели в `src/ui/webview/styles/` (`01-tokens`, `02-header`, `05-messages`, `09-composer`, `13-markdown` и так далее), порядок частей это порядок каскада, склейка в `src/ui/webview/styles/index.ts` даёт тот же текст, что один лист, а тесты читают его через `test/helpers/styles.ts`. Строка сообщения ленты вынесена в `src/ui/webview/components/MessageRow.tsx`, источники сниппетов в `src/ui/webview/codeSources.ts`.
- `extension.ts` разбит по кластерам в `src/host/`: `runtime.ts` (тип `RuntimeSession`), `queue.ts` (очередь сообщений), `approvals.ts` (карточки подтверждений), `channel.ts` (канал панели: `postFor`, `setState`, время шага), `sessions.ts` (сохранение, переключение, история страницами) и `child.ts` (запуск под-агента). Кластер это модуль с функциями `имя(host: MiniMaxController, ...)`: хост передаётся явно, члены класса нужны модулям открытыми (`readonly` без `private`). Вынос метода из класса делает кодмод `scripts/split-cluster.mjs` со спекой `scripts/spec-*.json`. Остальные крупные модули разрезаны по смыслу, старый путь остаётся фасадом: `tools/git.ts` → `tools/git/{common,read,write,worktrees}.ts`, `tools/repl.ts` → `tools/repl/{protocol,processes}.ts`, `tools/tasks.ts` → `tools/tasks/{types,parse,edit,file}.ts`, `tools/containers.ts` → `tools/containers/{args,runtime}.ts`, `search/project.ts` → `search/project/{protocol,lines,class}.ts`, `ui/webview/icons.tsx` → `ui/webview/icons/{base,modes,tools,actions}.tsx`, `ui/webview/highlight.ts` → `ui/webview/highlight/*`, `agent/agent.ts` → `agent/{types,retry,toolRunner,assistant}.ts`, `storage/sessions.ts` → `storage/caps.ts`. Реэкспорт со старого пути обязателен для публичного API расширения (инструменты, состояние панели, хранилище): тесты и внешние импорты идут по старым путям. Внутренние модули панели на старом пути не остаются: `ui/webview/Composer.tsx` и `ui/webview/ToolCard.tsx` ушли в `ui/webview/components/*`, их импортируют только файлы репозитория, поэтому импортёры переставляются на новый путь. `ui/webview/App.tsx` и `ui/webview/usePanelMessages.ts` пока на своих местах.
- Состояния проекта это конечные автоматы на общем ядре `src/fsm/machine.ts`. Автомат это данные: имя, начальное состояние и таблица переходов `{from, on, to}`. Работа идёт обычными функциями без глобального объекта: `step` делает один шаг по событию и отказывает с причиной, если таблица шага не знает, `can` проверяет шаг, `exits` перечисляет выходы состояния, `path` ищет кратчайшую цепочку событий в ширину, `moveTo` делает транзитивный переход по ней и называет пройденные состояния, `run` проводит цепочку событий и останавливается на первом отказе. Автоматы: сообщение ассистента (`assistantMachine` в `src/agent/assistant.ts`: `empty`, `answer`, `reasoning`, `mixed`; первая дельта хода из `empty` открывает сообщение событием `assistant_start`, дельта без текста не даёт события, `deltasOf` отдаёт список, а не null), статус чата (`statusMachine` в `src/ui/statusMachine.ts`: хост называет цель, `setState` в `src/host/channel.ts` идёт к ней через `moveStatus`, недостижимая цель пишется в лог, а состояние остаётся), голос (`voiceMachine` в `src/voice/controller.ts`), сообщение очереди (`queueMachine` и `moveQueued` в `src/host/queueMachine.ts`: причина отказа живёт только в состоянии `error`). Цель и задачи (`src/agent/stateMachines.ts`): `goalMachine` закрывает цель моделью (`closeGoal`: `complete` или `blocked`, завершённая цель не становится заблокированной, `update_goal` называет модели причину отказа), пользователь возвращает её в `active` (`resumeGoal`, новая цель стартует с `goalMachine.initial`); `todoMachine` ведёт задачу `pending` → `in_progress` → `completed`, `todoChanges` сравнивает снимки списка по тексту задачи и находит транзитивный путь, результат `todo_write` называет начатые и законченные задачи и задачу, закрытую без `in_progress`. Прямое присваивание состояния мимо таблицы это дефект. Перенос кода в классы состояний автоматом не является: переходы должны читаться таблицей. Проверяют тесты `test/unit/fsm.test.ts`, `test/unit/state-machines.test.ts`, `test/unit/goal-todo-machines.test.ts` и `test/unit/agent-assistant.test.ts`.
- Тесты режутся по той же схеме: общая оснастка лежит в `test/helpers/`, а сам файл тестов разбивается на части. Активация расширения была одним файлом в 3141 строку, теперь это `test/unit/extension-activate.test.ts` и пятнадцать файлов `extension-activate-N.test.ts`, общая оснастка в `test/helpers/vscodeMock.ts` (мок редактора) и `test/helpers/extensionHarness.ts` (загрузка расширения, ответы сервера). Мок редактора лежит в отдельном модуле, а `vi.mock('vscode', ...)` зовёт его динамическим импортом: состояние теста должно быть тем же объектом, что и у мока, иначе тест не увидит ответ панели. Резку делает скрипт в `scripts/test-split/`: общая библиотека `test-split-lib.mjs` и драйвер на каждый файл. Драйвер одноразовый: он останавливается, если файлы результата уже есть, иначе второй запуск записал бы в них пустые наборы и потерял бы тесты.
- Подсветку синтаксиса делает собственный лексер `src/ui/webview/highlight.ts`, без внешних зависимостей: токены получают классы `tok-*`, палитра лежит в css. Вид темы читает extension host (`src/ui/theme.ts`) и передаёт панели, класс `mm-theme-*` ставится на body прямо в html, до первой отрисовки.
- Сниппет из файла проекта подписан именем файла, сгенерированный код остаётся с меткой языка. Имя даёт модель (путь файла после маркера fence в системном промпте), а панель страхуется поиском по тексту: `src/ui/webview/codeBlock.ts` ищет блок в файлах, прочитанных агентом, и подставляет `файл.ts:строка`. Клик по подписи открывает файл в редакторе на этой строке.
- Иконки берутся из канонической геометрии lucide, а не рисуются от руки: центр закрашенной области должен совпадать с центром `viewBox`, иначе иконка сидит в углу квадрата. Проверяет измеритель `test/helpers/iconGeometry.ts` в тесте `test/unit/icons.test.ts`. Исключение одно: иконки отправки и остановки, они взяты из набора иконок VS Code и потому залиты, а не контурные.
- История чатов живёт в шапке: список сохранённых сессий с удалением и `+ New chat`, активная сессия восстанавливается при запуске расширения. Удаление занятого чата останавливает его ход: флаг `deleted` на `RuntimeSession` гасит `persist`, законченный ход не возвращает чат в хранилище, а `agent.stop()` не даёт удалённому чату тратить токены. Проверяет тест `test/unit/extension-activate.test.ts`.
- Id активной сессии пишется в состояние хоста только вместе с самой сессией: сначала список сессий, потом id. Одинокий id указывает в никуда: после перезапуска панель открывает чужой чат, а удалённый чат возвращается. Новый чат не пишет id, пока в нём нет сообщения, удалённый чат сбрасывает id. Проверяет тест `test/unit/extension-activate.test.ts`.
- Версия расширения видна в панели: хост читает `context.extension.packageJSON.version` и кладёт его в `UiState.version`, вебвью рисует бейдж с номером версии последним элементом строки вкладок (`src/ui/webview/components/Header.tsx`), справа от кнопки нового чата. Бейдж не хардкодится, не ломает высоту шапки и не сдвигает счётчик токенов. Проверяют тесты `test/unit/panel-layout.test.ts` и `test/unit/extension-activate.test.ts`.
- Номер версии живёт в `package.json` и поднимается вручную: он же попадает в имя `.vsix` и в бейдж панели. Стенд `test/visual/preview.tsx` берёт версию из манифеста, а не из константы, иначе стенд показывает чужую сборку.
- Версия поднимается по semver после каждого изменения: patch на правку, minor на новую возможность, major на несовместимое изменение. Правило действует и для пачки изменений: сначала решаем, что это для пользователя, и только потом ставим цифру.
- Инструменты git живут в `src/tools/git.ts`: модель зовёт их вместо команд git в терминале. Git запускается без оболочки, аргументы идут массивом в `src/git/cli.ts`, разбор вывода в `src/git/parse.ts`. Запуск git один на весь проект, `src/git/scm.ts` берёт тот же самый запуск.
- Чтение репозитория ничего не меняет и доступно в режиме plan: `git_status`, `git_diff`, `git_log`, `git_show`, `git_branch`, `git_blame`. Запись всегда с подтверждением и только в режиме code: `git_stage`, `git_commit`, `git_branch_create`, `git_checkout`. Коммит закрывает только индекс: пустой индекс это отказ, а не пустой коммит.
- Команды git не идут в оболочку: у `run_terminal` есть запрет на подкоманды, у которых есть свой инструмент (`gitToolFor` в `src/tools/terminal.ts`), отказ называет нужный инструмент. Без запрета модель по привычке пишет `git status` в терминал, а инструменты остаются невостребованными.
- Удаление файлов делает свой инструмент `delete_files` (`src/tools/delete.ts`): один файл или список файлов, путь вне рабочей области отклоняется через `resolveWorkspacePath`, каталог отклоняется понятным текстом и не удаляется молча, файла на диске нет это тоже отказ, и ни один файл не удаляется, если отказ есть в списке. Подтверждение спрашивается заново на каждый вызов, и постоянные разрешения его не обходят: список `ALWAYS_CONFIRM_TOOLS` в `src/ui/approvalScope.ts` отключает правила гейта (`src/ui/approvals.ts`), карточка не показывает кнопку `Always allow` (`ApprovalCard.tsx`), а разрешение сессии не запоминается (`src/host/messages.ts`). Карточка перечисляет удаляемые файлы с их размером, их числом и суммарным размером: план собирает `planDelete`, список для панели `deleteCardFiles` в `src/tools/delete.ts`, в карточку он приходит полем `files` (`UiApproval` в `src/ui/protocol.ts`). Файл не удаляется, а переносится в корзину проекта `.minimax/agent/trash/<чат>/<момент>/<путь>` через `rename` (`src/tools/trash.ts`): системная корзина потребовала бы оболочки, а `rename` работает в модуле без `vscode`. Папка агента игнорирует себя, git корзину не видит. Ответ инструмента и карточка называют корзину, вернуть файл значит перенести его обратно. При первом показе панели корзина чистится от удалений старше 14 дней и сверх 200 МБ (`pruneTrash` в `warmUp`), команда `MiniMax: Empty the Trash of the Project` очищает её целиком после модального вопроса. Раньше удаление было постоянным: ошибку модели с неотслеживаемым файлом git вернуть не мог. Проверяют тесты `test/unit/trash.test.ts` и `test/unit/tools-delete.test.ts`. Обход через терминал закрыт (и за обёртками `env`, `sudo`, `VAR=1`, `git -C`): `run_terminal` и `run_cmd` отказывают в `rm`, `rmdir`, `del`, `erase`, `unlink`, `rd`, `Remove-Item` и `git rm` и называют `delete_files` (`deleteToolFor` в `src/tools/deleteCommand.ts`, образец `gitToolFor`). Инструмент пишет, поэтому в режиме plan он скрыт, а по роли доступен только той, что пишет (`worker`), читающие роли его не получают. Проверяют тесты `test/unit/tools-delete.test.ts` и `test/unit/approvals-delete.test.ts`.
- Список изменённых файлов панели («Changed files») собирает хост из двух источников: файлы, которые изменили инструменты, и состояние репозитория. Инструменты записи сообщают свои файлы в результате вызова (`ChangedFile` в `src/tools/types.ts`): `write_file` пишет `added`, если файла не было, иначе `modified`, `edit_file` пишет `modified`, `delete_files` пишет `deleted`. Хост держит список чата в `RuntimeSession.changedFiles` и сливает его со списком репозитория (`mergeChangedFiles` в `src/host/changedFiles.ts`): файлы агента идут первыми, статус агента побеждает, он знает, что создал файл. Раньше список брался только из состояния репозитория (`git status`), и файл, которого git не видит, до панели не доходил: новый файл в папке, которую игнорирует `.gitignore`, изменение под флагом индекса или рабочая область вне репозитория. Удаления доходили: удалённый файл остаётся в `git status` до следующего коммита. Состояние репозитория читается от проекта чата (`runtime.workspaceRoot`), а не от первой папки окна. Откат хода убирает из списка файлы, которые вернулись на диск. Проверяют тесты `test/unit/changed-files-panel.test.ts`, `test/unit/tools-changed-files.test.ts` и `test/unit/changed-files-merge.test.ts`.
- Терминал бежит в той оболочке, которую промпт называет: на Windows это PowerShell (сначала `pwsh`, потом `powershell.exe`, проба один раз в `windowsShell`), на POSIX `sh`, и промпт пишет то же самое. Молчаливый `cmd.exe` убивал синтаксис PowerShell: `$env:X` раскрывался в литерал. Проверяет тест `test/unit/tools-terminal.test.ts`.
- Модель оборачивала каждую команду в `cd app; npm run check 2>&1 | Select-Object -Last 20; "EXIT=$LASTEXITCODE"`: инструмент не называл код успешного запуска, резал длинный вывод с конца, где стоят ошибки сборки, и пропускал цвета терминала. Теперь `run_terminal` делает это сам (`src/tools/commandOutput.ts`): ответ всегда кончается строкой `[exit code N]`, `tail_lines` оставляет последние строки, цвета ANSI вырезаются, длинный вывод сохраняет голову (20%) и хвост. На Windows команда идёт в обёртке `powershellScript`: код запуска это код последней нативной команды или 1 при упавшем командлете, иначе труба в `Select-Object` давала 0. Ведущий `cd папка;` или `cd папка &&` уходит в `cwd`, а ручное эхо `$LASTEXITCODE` и `$?` в конце команды отбрасывается. Отказ стоит в `resolveWorkspacePath`, поэтому его получают все инструменты с путём, а обходы файлов (индекс проекта, `grep`, findstr) пропускают закрытые файлы. Ключи узнаваемого вида маскирует `maskSecrets` (`src/tools/secrets.ts`) в выводе `read_file` и `grep`: только формы, которые почти не бывают кодом, ложная маска ломала бы правки модели. Проверяет тест `test/unit/deny-paths.test.ts`.
- Отпечаток файла, который агент видел, хранит `src/tools/fileStamps.ts` по чату и пути: `read_file`, `write_file` и `edit_file` его обновляют. `write_file` поверх файла, изменённого вне агента, отказывает и просит перечитать: полная запись выбросила бы работу читателя. `edit_file` проходит (точный `old_string` и так сторожит правку), но ответ говорит, что картина файла устарела. Файл, которого агент не видел, пишется как раньше. Удаление чата забывает его отпечатки. Проверяет тест `test/unit/file-stamps.test.ts`.
- Бэкапы правок агента живут на диске редактора: `FileBackupStore` (`src/storage/fileBackups.ts`) пишет файл на бэкап в `globalStorageUri/backups`, читает их при старте и чистит по возрасту (14 дней), числу (1000) и размеру (50 МБ). Без папки хранилища (тесты) работает `InMemoryBackupStore`. Запись идёт очередью, чистка не обгоняет запись. Проверяет тест `test/unit/file-backups.test.ts`.
- Карточка подтверждения отвечает на клавиши (`approvalKey` в `src/ui/webview/approvalKeys.ts`): Enter разрешает, A разрешает всегда, Esc отклоняет. Клавиши принадлежат карточке, когда читатель не печатает, пустое поле отдаёт Enter и Esc, но не букву. Инструменты, которые спрашивают всегда (`alwaysConfirms`), отвечают на клавиши только с фокусом на самой карточке: случайный Enter не удаляет файл. Отвечает только последняя карточка, слушатель стоит в фазе захвата, чтобы поле ввода не отправило пустой текст тем же Enter. Проверяет тест `test/unit/approval-keys.test.ts`.
- Чат выгружается в Markdown: команда `MiniMax: Export Chat to Markdown` (открытый чат) и кнопка `IconDownload` у чата в меню истории (сообщение `export_session`). ## Панель агента

Порядок сверху вниз:

1. Шапка: вкладки `Chat` и `Settings`, точка состояния, кнопка истории чатов с выпадающим списком сессий, кнопка нового чата, график расхода токенов и счётчик за сессию. Активная вкладка помечена скруглённой полосой под подписью, а не линией на всю ширину.
2. Лента сообщений: пузырь пользователя, markdown ответ, сворачиваемое размышление, карточки действий агента с иконкой, сводкой, таймингом и цветной точкой статуса, карточка подтверждения. В DOM живут не больше 120 последних сообщений, старые открывает кнопка `Show earlier messages`. Лента едет вниз, пока читатель внизу, кнопка `Jump to the latest` её возвращает. У блока кода шапка: имя файла со строкой, если это цитата из проекта, иначе метка языка; имя кликабельно и открывает файл.
3. Композер: чипы выделенного кода, строка текущего действия агента и поле ввода. В поле текст `contenteditable` с чипами файлов, скрепка в правом верхнем углу и нижний ряд: режим и модель слева, рассуждение, микрофон и кнопка отправки справа.
4. Вкладка `Settings`: ключ, endpoint, лимиты, обрезка истории, внешний вид, поиск, автоодобрение, правила проекта.

Чат и настройки смонтированы одновременно и переключаются классом `view-hidden`, поэтому черновик в поле ввода не теряется при переходе между вкладками.

- Публикация на Marketplace идёт по тегу `vX.Y.Z` через Trusted Publishing (`.github/workflows/publish.yml`): GitHub выдаёт задаче токен OIDC, Marketplace меняет его на ключ на 15 минут, PAT нигде не хранится. Политика издателя `katagarov` называет владельца `thepirateclub`, репозиторий `minimax-vscode` и файл `publish.yml` без environment, переименование файла ломает публикацию. Перед публикацией тег сверяется с версией `package.json`, затем типы и тесты. Тот же тег делает релиз на GitHub (`.github/workflows/release.yml`): файл `.vsix` и описание из раздела версии в `CHANGELOG.md` (`.github/release-notes.mjs`), версия без раздела в CHANGELOG останавливает релиз. Повторный запуск заменяет файл и описание существующего релиза. Обмен отвечал 401 `The token could not be exchanged for the specified publisher`, а журнал публичного запуска без входа не читается, поэтому при сбое шаг `.github/oidc-claims.mjs` печатает claims токена (без самого токена) аннотацией запуска, её видно без входа.

## Code style

- TypeScript в strict-режиме, без `any` (узкие касты только с комментарием почему)
- 2 пробела, одинарные кавычки, точка с запятой в конце строки
- Идентификаторы, имена файлов, комментарии в коде, тексты UI: английский
- Комментарии объясняют «почему», а не «что»
- Модуль: одна ответственность; рост файла означает, что пора делить
- Слой `api/` не знает про `vscode`, слой `ui/` не знает про HTTP-детали
- Чистую логику вебвью выносить в отдельные `.ts` модули без React: тесты идут в окружении `node` без jsdom, компонент не проверить
- Концы строк LF: `.gitattributes` задаёт `* text=auto eol=lf`, git сам приводит файлы к LF при коммите, конвертировать файлы перед коммитом не нужно

## Архитектурные правила

- Инструменты объявляются только через `src/tools/registry.ts`: имя, JSON Schema, исполнитель, политика подтверждения, признак побочного эффекта
- Реестр остаётся единственным источником правды о доступности: список инструментов для модели, фильтр в системном промпте и отказ выполнять заблокированный инструмент берутся из одного места
- Сырые content-блоки ответа модели сохраняются без изменений и возвращаются в следующий запрос без перестройки: MiniMax требует непрерывности reasoning-цепочки
- События extension → webview идут только через типизированный контракт `src/ui/protocol.ts`
- Стриминг батчится в extension host перед отправкой в webview, чтобы не залить postMessage
- История диалога хранит блоки Anthropic-совместимого формата, а не пересказ
- Ссылки `@путь` разбирает `src/agent/mentions.ts`: слой агента не знает про типы webview, а webview не ходит в файловую систему
- Переход к файлу это сообщение `open_file` из `src/ui/protocol.ts`: вебвью отправляет путь и строку, extension host проверяет путь на выход за пределы workspace и открывает файл с курсором на строке
- Длинная переписка обрезается в двух местах: история диалога режется по числу сообщений и по окну контекста (`src/api/history.ts`), сохранённая сессия режется по капам (`src/storage/sessions.ts`). Ошибка записи состояния не роняет ход, чат остаётся в памяти

| `git_worktree_list` | нет | доступен | разбор `git worktree list --porcelain` |
| `git_worktree_add`, `git_worktree_remove` | да, всегда | недоступен | путь worktree относительно workspace и не выходит за его пределы |
| `run_terminal` | да, всегда | недоступен | cwd = корень workspace, таймаут, обрезка вывода; команды git и worktree запрещены, у них есть свои инструменты |

| `get_goal` | нет | доступен | чтение цели сессии с лимитами и расходом бюджета |
| `update_goal` | нет | доступен | статус цели: выполнена или заблокирована, лимиты меняет только пользователь |

Правила безопасности:

- Любая запись на диск и любой запуск команды требуют явного подтверждения пользователя
- В режиме plan инструменты с побочным эффектом скрыты от модели, а их вызов отклоняется без запроса подтверждения
- Все пути разрешаются относительно корня workspace, выход за его пределы запрещён
- Перед записью сохраняется оригинал для команды отмены
- API-ключ хранится в `context.secrets` и никогда не попадает в settings, логи и webview
- Семантический слой поиска отправляет код проекта на сервер MiniMax, поэтому он выключен по умолчанию и включается только настройкой `minimax.semanticSearch`

## Testing instructions

- Юнит-тесты: `npm test` (vitest). Парсер SSE, конвертация сообщений, diff, схемы инструментов, агентный цикл на фейковом клиенте, сборка контекста, markdown, подсветка синтаксиса, обрезка истории, автоскролл, геометрия иконок, лексический и семантический поиск, эмбеддинги, округление чисел, журнал расхода токенов, строки метрик бейджа, текст коммита, разбор диффа, манифест расширения.
- Окружение тестов `node`, jsdom нет: React-компоненты вебвью не тестируются, вместо них проверяется логика в отдельных `.ts` модулях
- Геометрия иконок проверяется измерителем `test/helpers/iconGeometry.ts`: центр закрашенной области должен совпадать с центром `viewBox`
- Манифест расширения проверяется тестом `test/unit/manifest.test.ts`: команда должна попасть в палитру, а кнопка в Source Control в меню `scm/title` с точной группой `navigation`
- Интеграционные: `npm test` (vitest). Локальный HTTP-сервер отдаёт SSE-фикстуры, запрос идёт через настоящий клиент.
- Live: `npm run test:live`. Требует `MINIMAX_API_KEY` в `.env.local`, файл в `.gitignore`.
- Новое поведение сначала покрывается падающим тестом, затем пишется реализация.
- Оценка поведения агента: `npm run test:eval` (`test/eval/`, входит и в `npm test`). Сценарий это временная рабочая область с файлами, настоящие файловые инструменты и `grep`, модель по сценарию (`ScriptedModel` в `test/eval/harness.ts`): шаг сценария видит запрос агента и падает, если агент прислал не то, чего ждёт модель, иначе сломанный цикл прошёл бы молча. Проверки читают трассу хода (`test/eval/checks.ts`): чтение до правки, восстановление после упавшего `edit_file`, нет повторов сверх лимита, каждый отказ виден карточкой, причина остановки, режим plan не предлагает, не спрашивает и не выполняет запись. Изменение агентного цикла, промпта инструментов или гейта подтверждений сопровождается сценарием здесь, юнит-теста модуля мало: юнит проверяет функцию, сценарий проверяет ход.
- Перед коммитом: `npm run typecheck && npm test` зелёные.

## PR & commit conventions

- Ветка от `main`, в `main` не пушим напрямую
- Коммитим только свои файлы: `git add -- <явные пути>`, никогда `git add -A`
- Сообщения коммитов на русском в стиле Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`)
- Секреты никогда не коммитятся, `.env.local` в `.gitignore`

- Экспорт чата (`src/ui/chatExport.ts`) даёт Windows имя, которое она создаст: имена устройств (`CON`, `NUL`, `COM1` и так далее с любым расширением) получают приписку, точка и пробел в конце снимаются. `</details>` внутри размышления экранируется, иначе свёрнутый блок закрывался раньше, заголовок чата всегда одна строка. Проверяет тест `test/unit/chat-export.test.ts`.
- Набор `test/eval/` проверяет и новые ветки цикла: переход хода на запасную модель на 2061 и отсутствие перехода на 2062, порядок результатов параллельных под-агентов, экспорт чата с диффом и тегом в размышлении (`test/eval/new-features.eval.test.ts`).

## Definition of Done

- API-ключ не покидает `context.secrets`
