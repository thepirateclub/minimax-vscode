# MiniMax Agent

Расширение для Visual Studio Code с полноценным агентом на моделях MiniMax. Агент живёт в боковой панели, ведёт собственную историю диалога и вызывает инструменты по вашему проекту. Каждая запись на диск и каждый запуск команды требуют явного подтверждения.

## Возможности

- Чат с MiniMax M3.1 Flash и MiniMax M3 в правой панели VS Code (Secondary Side Bar)
- Потоковые ответы со сворачиваемым блоком размышлений
- Ссылки на файлы прямо в поле ввода: `@` открывает подсказки по открытым вкладкам и по проекту, выбранный файл встаёт чипом внутрь поля и показывает только имя с расширением
- Выбор модели и уровня размышений расположен под полем ввода промпта, узкие селекторы с иконками
- Один селектор `Reasoning` под полем ввода: у M3.1 Flash это уровни глубины, у M3 только `Off` и `Adaptive`, потому что сервер M3 глубину не принимает
- История чатов в шапке: список сохранённых сессий, удаление, новый чат, активный чат переживает перезагрузку окна
- Лента сообщений сама следует за ответом, кнопка `Jump to the latest` возвращает её вниз
- Ответы приходят в markdown: заголовки, списки, таблицы, блоки кода с меткой языка и кнопкой `Copy`
- Подсветка синтаксиса в блоках кода: ключевые слова, строки, комментарии, числа и имена функций раскрашены, палитра следует теме VS Code
- Блок кода из файла проекта подписан именем файла и номером строки, клик по подписи открывает файл в редакторе на этой строке; сгенерированный код остаётся с меткой языка
- Карточки действий агента: иконка, что сделано, сколько строк, сколько миллисекунд заняло
- `read_file` читает несколько файлов одним вызовом
- График расхода токенов в шапке панели: столбик на действие плюс счётчик за сессию, значения округляются с приставками K, M, B
- Индекс проекта: лексический поиск (BM25 и триграммы) работает офлайн, семантический слой включается настройкой и отправляет код на сервер MiniMax
- Команда `MiniMax: Rebuild Project Index` перестраивает индекс проекта
- Размер шрифта панели настраивается, вся вёрстка масштабируется вместе с ним
- Статус агента показан цветной точкой: зелёная мигает у готового действия, красная при ошибке
- Отправка запроса это круглая иконка в правом нижнем углу поля ввода, селекторы режима, модели и рассуждения стоят под полем
- Поле ввода промпта выше, в него влезает несколько строк задачи
- Лимит ответа берётся из каталога модели, а не из настройки
- Обрезка истории: сколько сообщений оставить и какую долю окна контекста может занимать переписка
- Файл прикрепляется скрепкой в углу поля ввода, отдельной кнопки Attach больше нет
- Два режима агента: `plan` изучает проект и отвечает планом, `code` даёт доступ к записи файлов и терминалу
- Выделенный в редакторе код уходит в чат отдельным чипом
- Вкладка настроек рядом с чатом: ключ, endpoint, модель, effort, лимиты, автоодобрение
- Инструменты: `read_file`, `write_file`, `edit_file`, `list_files`, `search_code`, `run_terminal`
- Превью диффа перед записью и карточка подтверждения перед каждой командой
- Правила проекта подхватываются из `AGENTS.md`, `.github/copilot-instructions.md`, `CLAUDE.md` и `.cursorrules`
- Бейдж в правом нижнем углу VS Code показывает остаток 5-часового лимита в процентах, а клик по нему открывает числа: расход за сутки, остаток за неделю, остаток за 5 часов и кэш-хит в процентах
- Кнопка со звёздочкой в панели Source Control пишет текст коммита по изменениям репозитория и кладёт его в поле сообщения
- Отмена последнего изменения файла командой `MiniMax: Undo Last File Change`
- Локальная история сессий, она не покидает машину

## Требования

- VS Code 1.106 или новее
- API-ключ MiniMax: ключ подписки M Plan или pay-as-you-go

## Настройка

1. Откройте палитру команд и выполните **MiniMax: Add API Key**. Ключ сохраняется в secret storage VS Code и больше нигде не хранится.
2. Выполните **MiniMax: Set Endpoint** и выберите Global (`api.minimax.io`) или China (`api.minimaxi.com`).
3. При желании выполните **MiniMax: Select Model**, **MiniMax: Set Thinking Effort** и **MiniMax: Set Agent Mode**.
4. Откройте панель MiniMax в правой панели VS Code и поставьте задачу.

Все настройки доступны прямо в панели: вкладка **Settings** рядом с **Chat**. Там же задаётся ключ, если он не добавлен командой.

Ключ можно положить и в файл `.env.local` в корне проекта, переменная `MINIMAX_API_KEY`. Файл уже в `.gitignore` и в репозиторий не попадает. Приоритет у secret storage, `.env.local` используется как запасной источник.

| `MiniMax: Set Thinking Effort` | выбрать уровень размышлений (`low` … `max`) |

| `MiniMax: Undo Last File Change` | откатить последнее изменение файла |
| `MiniMax: Refresh Workspace Context` | перечитать правила и структуру проекта |
| `MiniMax: Rebuild Project Index` | перестроить индекс проекта для поиска |
| `MiniMax: Show Logs` | открыть канал вывода MiniMax |

| `MiniMax: Add File to Chat` | добавить ссылку на файл в поле ввода |

## Работа с файлами

Ссылка на файл живёт в самом поле ввода, поэтому на неё можно сослаться в любом месте фразы.

- Наберите `@` в поле ввода: появится список открытых вкладок и файлов проекта. Стрелки выбирают пункт, Enter вставляет ссылку.
- Вставленная ссылка выглядит как чип прямо в поле ввода: видно только имя файла с расширением, полный путь остаётся внутри чипа. Крестик на чипе убирает ссылку.
- Ссылку можно вписать руками, формат тот же (`@путь/к/файлу`). При отправке extension host сам находит файл внутри workspace и прикладывает его содержимое к запросу.
- `MiniMax: Add File to Chat` в контекстном меню файла вставляет такую же ссылку.
- `Ctrl+Alt+M` (`MiniMax: Add Selection to Chat`) превращает выделенный код в чип над полем ввода. Чип виден, его можно снять, а сам код уходит модели отдельным блоком.

## Текст коммита

В панели Source Control есть кнопка со звёздочкой. Она смотрит на изменения репозитория и пишет текст коммита в поле сообщения.

- Кнопка живёт в заголовке панели Source Control рядом с кнопками коммита и обновления. Действия в заголовке появляются, когда панель в фокусе.
- Расширение берёт индекс изменений (staged) и, если ничего не подготовлено, дифф рабочей директории. Новые файлы, которых ещё нет в индексе, добавляются отдельно, иначе коммит с новым файлом остался бы незамеченным.
- Команда `MiniMax: Generate Commit Message` делает то же самое из палитры.
- Текст пишется по правилам Conventional Commits, строка на русском, в императиве: `feat: добавить генерацию текста коммита`.
- Модель получает только изменения, инструменты ей не нужны.
- Если репозитория нет, готовый текст кладётся в буфер обмена.

## Поиск по проекту

Агент ищет по проекту через индекс, который расширение строит само.

- Индекс собирается в фоне при запуске расширения и обновляется, когда файл на диске меняется, создаётся или удаляется. Команда `MiniMax: Rebuild Project Index` перестраивает его с нуля.
- Лексический слой работает офлайн и включён всегда: ранг файлов считается по BM25, слова разбиваются на части по camelCase и snake_case, а если точное слово не найдено, фолбэк ловит опечатку по триграммам.
- Семантический слой включается настройкой `Semantic search` во вкладке Settings. Он режет файлы на перекрывающиеся куски и спрашивает у MiniMax эмбеддинги `embo-01`, а списки лексического и семантического поисков сливаются.
- Слой по умолчанию выключен: он отправляет код проекта на сервер. На ключе подписки M Plan эндпоинт эмбеддингов отвечает отказом по лимиту запросов, и в этом случае поиск возвращает лексический результат с пометкой, что семантический слой не сработал.
- У инструмента `search_code` есть параметр `mode`: `auto` берёт лексику и добавляет семантику, когда она включена, `lexical` ищет только словами, `semantic` только по смыслу, `hybrid` всегда смешивает оба списка.

## Оформление панели

- Размер шрифта задаётся настройкой `Font size` во вкладке Settings. Панель масштабируется целиком, все размеры в css считаются от базовой переменной.
- Статус агента в шапке и в карточке действия показан цветной точкой: зелёная мигает, когда действие завершилось, красная при ошибке, синяя горит во время работы. Текст статуса остаётся в подсказке.
- Счётчик токенов и подписи графика округляются с приставками: `K` это тысяча, `M` миллион, `B` миллиард.
- Под графиком расхода токенов стоит сетка, по ней столбики читаются на глаз.
- График растянут на всю ширину шапки: столбики делят свободное место, а не растут вместе с числом шагов.
- Кнопка отправки стоит в правом нижнем углу поля ввода и нарисована иконкой самолётика с прямым углом у кончика. Пока агент работает, на её месте квадрат остановки.

## Обрезка истории

История диалога обрезается в двух местах, оба порога настраиваются во вкладке Settings.

- `Compacting` задаёт, сколько последних сообщений переписки остаётся в диалоге.
- `Context threshold` задаёт, какую долю окна контекста модели переписка может занимать, в процентах. Доля считается от окна модели, грубая оценка токенов берётся по длине текста.

## Лимит и статус-бар

В правом нижнем углу VS Code живёт бейдж `MiniMax`. В скобках после названия стоит остаток 5-часового окна лимита в процентах, например `MiniMax (96%)`. Наведение показывает недельный остаток и время до сброса окна.

Бейдж обновляется при запуске расширения, после каждого хода агента и раз в пять минут. Данные берутся с `GET https://api.minimax.io/v1/token_plan/remains` тем же ключом, что и для запросов к модели.

Клик по бейджу открывает список чисел:

- расход токенов за последние сутки;
- остаток за неделю в процентах;
- остаток за 5-часового окна в процентах;
- кэш-хит за сутки в процентах, доля прочитанного из кеша во входных токенах.

Остатки окон приходят с сервера, а расход за сутки и кэш-хит считает само расширение по журналу запросов: сервер отдаёт только проценты и время до сброса. Отдельным пунктом в списке идёт переход в панель агента.

## Режимы агента

Режим переключается селектором `Mode` под полем ввода, во вкладке Settings и командой `MiniMax: Set Agent Mode`.

- `plan` (только чтение): агенту доступны `read_file`, `list_files` и `search_code`. Он изучает проект и отвечает конкретным планом: какие файлы менять и что именно в них править. Инструменты записи и терминала в этом режиме модели не видны, а попытка вызвать их отклоняется.
- `code` (полный доступ): доступны все инструменты, каждая запись и каждая команда идут через подтверждение как обычно.

Режим действует со следующего хода: список инструментов и системный промпт пересобираются вместе с сессией, история диалога при этом сохраняется.

## История чатов

Кнопка с часами в шапке открывает список сохранённых чатов. Оттуда можно открыть прошлый чат, удалить его или начать новый. История лежит в состоянии расширения VS Code и переживает перезагрузку окна: активный чат открывается снова при следующем запуске.

Чтобы хранилище не раздувалось, у всего есть потолок: 50 чатов, 400 сообщений в чате, 120 сообщений истории диалога и 200 000 символов на одно сообщение. Старое отбрасывается, поэтому панель не падает на длинной переписке.

## Расход токенов

В шапке панели живёт график расхода: один столбик на действие агента, высота пропорциональна сумме токенов этого действия. Входные токены (контекст запроса, включая чтение из кеша) рисуются приглушенным цветом, выходные (ответ модели) акцентом. Рядом стоит счётчик за всю сессию.

Наведение на столбик показывает подробности, например `Action 1: in 389814 (353044 cached), out 11922`. История расхода хранится вместе с сессией, поэтому график переживает перезагрузку окна.

## Размышление модели

У MiniMax M3.1 Flash есть уровни глубины рассуждения (`output_config.effort`). У MiniMax M3 их нет: сервер игнорирует `effort` и `reasoning_effort`, глубину модель выбирает сама. Поэтому в композере стоит один селектор `Reasoning`, но его содержимое зависит от выбранной модели.

- M3.1 Flash: `low`, `medium`, `high`, `xhigh`, `max`. Модель думает всегда.
- M3: `Off` (запрос без блока размышления) и `Adaptive` (запрос с `thinking: {type: 'adaptive'}`).

Тот же селектор есть во вкладке Settings. Настройки `minimax.effort` и `minimax.thinking` сохранены как есть: первая отвечает за уровень у M3.1 Flash, вторая за режим `Adaptive` у M3.

## Формат ответа

Агенту предписан формат ответа: заголовки, короткие абзацы, списки и блоки кода с языком. Разметка рендерится в панели: у блока кода есть метка языка и кнопка `Copy`, списки-чеклисты остаются чекбоксами.

Если блок кода цитирует файл проекта, панель подписывает его именем файла и номером строки, а клик по подписи открывает файл в редакторе на нужной строке. Код, который модель написала сама, остаётся с меткой языка.

Оформление цветное, а не серое. Заголовки, маркеры списков, ссылки и inline-код берут акцентный цвет темы, а код внутри блока подсвечивается по синтаксису: ключевые слова, строки, комментарии, числа и имена функций получают свои оттенки. Палитра зависит от того, светлая тема у редактора или тёмная, контрастные темы получают самые яркие оттенки.

## Инструменты

| Инструмент | Подтверждение | Режимы | Что делает |
| --- | --- | --- | --- |
| `read_file` | нет | plan, code | читает текстовый файл с нумерацией строк, есть диапазон `start_line`/`end_line`; можно передать `paths` и прочитать до 12 файлов одним вызовом |
| `write_file` | да | code | создаёт файл или заменяет его целиком, перед записью показывается дифф |
| `edit_file` | да | code | заменяет точную строку, `old_string` должен встречаться ровно один раз |
| `list_files` | нет | plan, code | показывает структуру проекта, `node_modules` и `.git` игнорируются |
| `search_code` | нет | plan, code | ищет текст по индексу проекта, режимы `auto`, `lexical`, `semantic`, `hybrid` |
| `run_terminal` | да, всегда | code | выполняет команду в корне workspace с таймаутом и обрезкой вывода |

## Разработка

```bash
npm install
npm run compile
npm run watch
npm test
npm run typecheck
npm run package
```

Открыть расширение в VS Code по F5 или поставить собранный файл:

```bash
code --install-extension minimax-agent-0.3.0.vsix --force
```

Имя файла повторяет версию из `package.json`.

Расширение в редакторе грузится из установленного `.vsix`, рабочая копия сама не подхватывается. После установки нужно перезагрузить окно.

## Live-тесты

Live-тесты бьют по настоящему API и требуют ключ:

```bash
npm run test:live
```

Ключ берётся из `MINIMAX_API_KEY` в окружении или из `.env.local` в корне проекта. Обычный `npm test` live-тесты не запускает.

## Безопасность

- Любая запись на диск и любой запуск команды требуют подтверждения в панели, есть кнопка «Always allow in this session».
- Пути инструментов разрешаются только внутри корня workspace, выход за пределы запрещён.
- Перед записью сохраняется оригинал файла, его можно откатить.
- API-ключ живёт только в secret storage VS Code, в webview и в логи он не попадает.
